# Intro video design

## Goal

A 60-second introduction to Celesta for YouTube, aimed at developers who have
never heard of it. It sells the idea — a video is source code — rather than
listing features, and ends by sending viewers to the GitHub releases page to
download the app.

The video is itself a Celesta composition. Its central move is to reveal that
the motion graphics on screen are being drawn by the `film.tsx` shown next to
them, so the medium is the proof.

## Non-goals

- Narration or voice. The video carries its message with on-screen English
  text and music; Japanese subtitles, if wanted, are added on YouTube.
- Real screen recordings of the desktop app. Every UI on screen (editor,
  timeline editor, terminal) is drawn in Celesta, so the video does not need
  re-recording when the app's UI changes.
- A complete feature tour. `examples/feature-tour` already covers that.
- New runtime features. The video uses only APIs that exist today.

## Format

- 1920×1080, 30 fps, 1800 frames (60 seconds).
- Cut to an original 120 BPM score: one beat is 15 frames, one bar is 60
  frames, 30 bars in total. Every scene starts on a bar line.
- Lives in `examples/intro/`, with `film.tsx` as the entry.
- The score is generated by `make-score.py` using Python's standard library
  only, writing `music.wav` next to the entry (`*.wav` is already gitignored).

## Look

The palette and type follow the website's Noir theme
(`packages/website/theme/noir.css`, dark mode):

| Token | Value | Use |
| --- | --- | --- |
| `bg` | `#000000` | Background |
| `fg` | `#f5f5f7` | Text, primary shapes |
| `accent` | `#3d7bff` | The single accent: the ball, highlights, the caret |
| `muted` | `#6b6b70` | Secondary text, frame counter |
| `line` | `#1c1c1e` | Hairlines, panel borders |
| `panel` | `#0d0d0f` | Code panels and mock UI surfaces |

Rules:

- No gradients anywhere.
- Square corners: every `Rect` has radius 0.
- Heavy, solid headlines; 1 px hairlines for structure.
- Only the `CELESTA` wordmark is uppercase. No wide-tracked uppercase labels.
- Arrows, diamonds, and check marks are drawn with `Path` / `Arrow`, never
  with text glyphs such as `→`, `◆`, or `✓`.
- Headlines use Space Grotesk Bold; code uses JetBrains Mono. Both load from
  Google Fonts through `<Font>`.
- Code is drawn with `@celesta/code`, with a theme derived from
  `codeThemes.dark` whose tokens use the palette above (keywords and numbers
  in `accent`, strings in `fg`, punctuation and comments in `muted`).

## Honesty rule

Code shown on screen is a simplified version of the code that actually draws
that scene. Each scene keeps its snippet as a string constant in the same
file, and every value the snippet shows (a font size, a color, a spring
setting) comes from the constant that drawing also uses. When a scene
animates a value changing in the code, the picture changes from the same
variable on the same frame.

The ball shared by Cold open, Reveal, and Idea has one position function in
`shared/ball.ts`. Its snippet in Reveal and Idea is the source of that
function.

## Storyboard

A small `frame 0000` counter in the bottom-right corner (muted, JetBrains
Mono) runs for the whole video except the end-screen hold. It shows the
current frame of the composition, so the claim "every frame is computed"
stays visible without being said. Cuts are hard cuts on the bar line unless
noted.

The tagline `Video, written in code.` is a working line, chosen not to repeat
`reel`'s "Code is the cut."; it can change without affecting anything else.

## Structure

```
examples/intro/
  film.tsx          Entry: Composition, Font, Audio, and the scene Sequences
  constants.ts      W, H, FPS, BEAT, BAR, DURATION, palette, fonts
  timeline.ts       Scene boundaries S (in bars) and the SCENES list
  scenes/           ColdOpen, Reveal, Problem, Idea, Components, LiveEdit,
                    Export, Outro — one file each
  components/       FrameCounter, CodePanel (Code + Noir theme), Headline,
                    KeyCap, Diamond, Check, and other shared parts
  shared/ball.ts    The ball's position as a function of frame
  make-score.py     Generates music.wav
  README.md         Timing table, export command, what is real vs. staged
  package.json
  tsconfig.json     Extends ./.celesta/tsconfig.json
```

`film.tsx` follows `examples/reel/film.tsx`: it maps `SCENES` to
`<Sequence>`s and adds the frame counter and audio. Each scene reads its local
frame from `useCurrentFrame()` and derives everything from it; there is no
state, randomness, or timing outside the frame number, except seeded
`random`/`noise` from `@celesta/math`.

Text that has to fit a box (headlines, the terminal line) is measured with
`useTextMetrics` or `fitText` rather than tuned by hand.

## Verification

1. Build the exporter from source (the installed app may lag the repo):
   `PKG_CONFIG_PATH="$(brew --prefix ffmpeg@8)/lib/pkgconfig" cargo build -p celesta-exporter --release`.
2. `node skills/celesta/scripts/inspect.mjs examples/intro/film.tsx --every 15`
   evaluates the whole video and reports no errors and no missing media.
3. Type-check with the staged `.celesta` types and `tsc --noEmit -p examples/intro`.
4. Render PNGs at each scene's key frames and look at them; render a contact
   sheet with `--every 30 --contact-sheet` to check the whole cut.
5. Export the MP4 with `--json` and check that it has 1800 frames and an
   audio stream. Whether the music sounds right is checked by the user.

## Deliverables

- `examples/intro/` as described above, committed.
- `poster.jpg` in that folder: a 1280×720 still of the Reveal scene (code and
  preview side by side), usable as the YouTube thumbnail.
- An exported `intro.mp4`, not committed (`*.mp4` is gitignored).
