# Drop website workarounds fixed in Makit 0.9.1 (2026-10-28)

## Specification and implementation

Makit 0.9.1 (Renovate bump in mika-f/Celesta#548) fixes several gaps that
`packages/website` worked around. This change removes those workarounds:

| Makit fix | Removed from the website |
| --- | --- |
| mika-f/makit#46, `github.directory` | `site/edit-url.ts` (`withPackagePath`) and its test. `makit.config.ts` sets `github.directory: 'packages/website'`. |
| mika-f/makit#48, clean builds remove `.makit/.next` | Deleting `.makit/` in the `build` script. |
| mika-f/makit#49, per-locale `<html lang>` | `setLanguages` / `setDocumentLanguage` and the Pagefind rebuild (`writeSearchIndex`) in `scripts/postbuild.mjs`, their tests, the `pagefind` devDependency, and the client `DocumentLocale` component. |
| mika-f/makit#51, Pagefind follows a locale switch | The search reason for the `EN / JA` links reloading the page. They stay plain `<a>` because `LocaleMemory` only writes on a full load. |
| mika-f/makit#44, runtime types from the consumer | `tsconfig.json` `paths` for `react` / `react-dom`. `next/navigation` imports now use `@natsuneko-laboratory/makit-runtime/navigation`. `next` stays a devDependency: it is a peer of `makit-runtime`. |
| mika-f/makit#45 / #50 | No code workaround. The README gap entries are removed. |

`theme/RootLayout.tsx` now sets `data-nr-locale` from `RootLayoutProps.locale`.
It keeps the inline locale script only where Makit gives no locale (the 404 and
`/`). The single `404.html` serves every locale, so the 404 still needs the
script. The remaining `DocumentTitle` component moves to `theme/DocumentTitle.tsx`.

Makit#45 has a side effect. The root layout now exports site metadata, so Next
inserts `<title>Celesta</title>` ahead of the 404's localized title after
hydration, and the tab read "Celesta". `DocumentTitle` now reapplies the
localized title whenever `<head>` changes, using a `MutationObserver`.

The stale `minimumReleaseAgeExclude` entries for Makit 0.9.0 are removed from
`pnpm-workspace.yaml`. 0.9.1 is past pnpm's release-age window.

`scripts/postbuild.mjs` still fills the Markdown endpoints and `llms-full.txt`.
Makit 0.9.1 still copies those without the remark plugins.

## Checks

- `pnpm build` passes. `postbuild` reported `set lang on 0 page(s)` on 0.9.1
  before this change, which confirms Makit already writes `lang`.
- `pnpm test`: 8 files, 52 tests pass. Run it with
  `CLOUDFLARE_LOAD_DEV_VARS_FROM_DOT_ENV=false` when a local
  `packages/website/.env` defines extra variables. Otherwise `wrangler types`
  adds them to `Env` and `tests/locales.test.ts` fails to type-check.
- `pnpm check` reports no issues. The static-page link warnings fixed by makit#47 are gone.
- `pnpm check:examples` passes.
- Built output, compared with a build of the Renovate branch before this change:
  - `/ja/**` pages carry `lang="ja" data-nr-locale="ja"`. The locale script
    runs only on `404.html`.
  - Edit links are unchanged (`…/edit/main/packages/website/content/…`).
  - Pagefind has separate `en` and `ja` indexes (27 pages each).
  - Canonical links are absolute.
- In the browser:
  - `/ja/no-such-page/` shows the Japanese 404 with the title
    "ページが見つかりません — Celesta", and `/en/…` shows the English one. Before
    the `DocumentTitle` fix, both read "Celesta". The live 0.9.0 site shows the
    localized title.
  - `/ja/` looks the same as before, and the skip link shows only the Japanese label.
  - A Pagefind search for タイムライン on `/ja/` returns `/ja/docs/…` pages.
