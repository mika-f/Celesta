# Rough cut (2026-11-22)

A film's structure and timing can be agreed before every scene is built,
as in a storyboard or Motion's `stage: "rough"` and per-scene `desc`
(`scenes.json`): scenes listed with a name, a length, and one sentence on
what happens, each drawn as a placeholder card until it is built.

## Specification

- `SceneEntry` (`packages/react/src/scenes.ts`) takes `desc?: string` and
  `status?: 'rough' | 'final'` (`SceneStatus`). No status is final.
  `defineScenes` keeps both on the placed scene and throws for a `desc`
  that is not a string or another status.
- `<Scenes>` plays an entry with `status: 'rough'`, or without a `Scene`,
  as `<ScenePlaceholder>` in its `<Sequence>`. A rough entry's own `Scene`
  is not drawn, so it can be built in place and shown by dropping the
  status. Before this change an entry without a `Scene` drew nothing; no
  example played such an entry (lists that only name chapters, such as
  `with-chapters.tsx`'s `PARTS`, are not passed to `<Scenes>`).
- The card's tag is "Rough cut" for a rough entry and "No Scene yet" for
  one without a `Scene`. Only `status: 'rough'` counts as rough everywhere
  else: a Scene-less entry is common in lists that only name chapters laid
  out by `<Sequence>` or `<TransitionSeries>`, and those must not warn.
- `<ScenePlaceholder name desc? index? count? durationInFrames label?>`
  (`packages/react/src/scene-placeholder.ts`, exported from the core and
  the browser entry): the ground, a dashed frame inside a margin, "Scene i
  of n" top left, the tag top right, the name (96 px at 1080) above the
  middle and the `desc` (42 px) below, both wrapped at the inner width,
  the length (`2 s · 60 frames`) and the elapsed seconds above a bar that
  is empty on the scene's first frame and full on its last. Sizes scale by
  `min(width, height) / 1080`, so vertical and square canvases fit. It
  reads only `useCurrentFrame()` and `useVideoConfig()`: a pure function
  of the frame. Colors are fixed (no theme), with no gradients, uppercase
  labels or rounded corners. It lives in the core rather than
  `@celesta.studio/components` because `<Scenes>` draws it and the core
  cannot depend on that package.
- Chapters (`packages/react/src/chapters.ts`): `ChapterInput` and `Chapter`
  carry `desc` and `status` when the source gives them (absent otherwise,
  so existing chapter lists are unchanged); `listChapters` checks them as
  `defineScenes` does.
- Bridge: `ReactChapter` gains `desc: Option<String>` and
  `status: ChapterStatus` (`Rough` / `Final`, default `Final` for older
  runtimes), with `ReactChapter::new`, `is_rough`, `rough_chapters(chapters,
  start, count)` (the rough chapters overlapping a frame span; a rough mark
  of length 0 counts where it sits) and `describe_rough` (the warning's
  sentence). Serialization leaves out a final status and a missing `desc`.
- Editor: the Chapters row draws a rough chapter in the muted foreground
  color instead of the accent, with "Rough" after its name; hovering a
  chapter shows "Rough cut: <desc>", "Rough cut: not built yet", or the
  `desc` of a final chapter (`chapter_tooltip`). The React Preview tab's
  Chapters list tags rough chapters and shows the `desc` under the name.
- Export (`crates/exporter`): `ExportProgress::CodedWarning(CodedWarning {
  code, message })` is a warning with a stable code. It prints like any
  warning and is listed in the report's `warnings`; the report also lists
  it as `{code, message}` in `codedWarnings` (absent when empty), and a
  `--json-progress` warning event carries its `code`. `warnings` stays a
  list of strings so existing consumers keep working. The
  `nondeterministic_render` warning (whose text already starts with its
  code) is sent as a coded warning too, so `codedWarnings` lists every
  coded warning.
- A React video export checks the exported span (after `--from`/`--to`)
  against `metadata.chapters` before rendering (`check_rough_scenes` in
  `react_entry.rs`): rough chapters give a `rough_scenes` coded warning
  naming them. `--final` (`ExportOptions::final_cut`; MCP `export_video`'s
  `final`; `@celesta.studio/exporter`'s `final`) turns it into
  `ExportError::RoughScenes`, code `rough_scenes`, before anything is
  written. Stills and contact sheets do not check: a contact sheet is how a
  rough cut is reviewed. So `--final` with a still selection or with
  subtitles alone is a usage error (and needs `--react`), and MCP
  `export_video` refuses `final` without an output video or for a JSON
  project, rather than ignoring a check the caller asked for.
- Native inspection (`celesta-exporter --inspect`, which `inspect.mjs`
  drives when it finds an exporter) puts `chapters` in its ready message's
  `config`, as the runtime's own ready message does, so both modes list
  rough chapters.
- Inspection: the MCP `inspect` tool and `skills/celesta/scripts/inspect.mjs`
  print the chapters on one line as before when none is rough or has a
  `desc`, else one per line with `rough` and `: <desc>`, and warn while
  scenes are rough. MCP `inspect` adds `chapters` to its structured result.

## Decisions

- Rough status is carried by `<Composition chapters>` only. Detecting
  placeholder cards in rendered frames would need a new per-frame field in
  the CLI protocol; the docs say to pass the list as `chapters` (which a
  film of named scenes already does for the editor). A list played by
  `<Scenes>` but not passed as `chapters` draws its cards without warnings.
- `desc` flows into chapters (editor list, tooltip, inspect) but not into
  `<FrameChrome>`: it is a note for agreeing on the cut, not on-screen copy;
  `formatChapter` can still show it if a film wants that.
- `--final` rather than a status on the whole list: Celesta has no single
  "film is done" switch, and a flag on the export is where the refusal
  matters.

## Example

`packages/cli/examples/rough-cut.tsx`: one built scene and three rough
ones (two with a `desc`), passed as `chapters`.

## Checks

- `pnpm --dir packages/react test` (Vitest, including the new
  `test/rough-cut.test.mts`: statuses and checks, which entries draw a card,
  the card's text, the bar as a pure function of the frame, chapters
  carrying `desc` and `status`, and a vertical canvas).
- `pnpm --dir packages/exporter test` (`final` passes `--final`).
- `packages/cli/test/inspect.test.mts`: `inspect.mjs` lists rough chapters
  with their `desc`, finds the card's text, and warns; the exporter's
  `native_inspection_reports_rough_chapters_and_their_desc` checks the same
  through `--native`.
- `final_applies_to_react_video_only` (exporter CLI) and
  `final_applies_to_a_react_video_only` (MCP).
- `cargo test -p celesta-react-bridge` (`reads_chapters_from_the_ready_config`,
  `rough_chapters_are_those_an_export_span_draws`, and the live
  `reports_rough_scenes_and_their_desc_when_node_is_available`),
  `cargo test -p celesta-exporter --lib` (`rough_scenes_in_the_span_warn_with_their_code`,
  `a_final_export_refuses_rough_scenes`), `cargo test -p celesta-mcp --lib`
  (`chapters_list_rough_ones_and_their_desc_one_per_line`), and
  `cargo test -p celesta-editor --bin celesta-editor a_chapter_tooltip`.
- `cargo clippy` on `celesta-react-bridge`, `celesta-exporter`,
  `celesta-mcp`, and `celesta-editor` with `--all-targets -D warnings`, and
  `cargo fmt --all -- --check`.
- Before and after: frame 90 and a contact sheet of the example, before with
  the installed Celesta 0.10.0-alpha.4 (the rough scenes are an empty
  ground) and after with this branch's exporter (placeholder cards); the
  `--json` export of the example reports `codedWarnings` with
  `rough_scenes`, and `--final` fails with `rough_scenes`.
- Not checked: the editor's Chapters row and list in the running app (the
  dev editor's window was not captured from this session).
