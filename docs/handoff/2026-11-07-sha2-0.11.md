# Adapt to sha2 0.11 (2026-11-07)

## Specification and implementation

Renovate's #661 moves `sha2` from 0.10 to 0.11 in `celesta-gpu-renderer`,
`celesta-plugin-host`, and the VRM plugin. sha2 0.11 is built on digest 0.11
and `hybrid-array`, and two things the code relied on are gone:

- A digest no longer formats with `{:x}`: `hybrid_array::Array<u8, _>` does
  not implement `LowerHex`. `celesta-plugin-host`'s `fingerprint`
  (`crates/plugin-host/src/approval.rs`) wrote `sha256:{:x}`.
- `Sha256` no longer implements `io::Write`. The VRM plugin's
  `performance_key` (`plugins/vrm/src/stepping.rs`) streamed
  `serde_json::to_writer` straight into the hasher.

`fingerprint` now writes the digest with `lower_hex`, two lowercase hex digits
a byte. That is exactly what `{:x}` wrote, so the fingerprints that the
settings saved for allowed plugins still match, and no plugin is asked about
again after the update.

`performance_key` writes through `HashWriter`, a small `io::Write` that hands
each chunk to `Digest::update`. It keeps the streaming: a frame's key is
computed without serializing the motions and tracks into a buffer first.

`celesta-gpu-renderer` needs no change: `Sha256::digest(..).into()` still
converts into `[u8; 32]`.

## Checks

- `digests_are_written_as_lowercase_hex` pins `lower_hex` to the FIPS 180-2
  SHA-256 of `"abc"`. A throwaway crate printed `{:x}` of `Sha256::digest`
  with sha2 0.10.9 for `"abc"`, `""`, and a longer input; `"abc"` gave the same
  string the test expects.
- `cargo fmt --all --check` and `cargo fmt -p celesta-plugin-vrm --check`
  (in `plugins/`).
- `cargo test -p celesta-plugin-host --locked`.
- `cargo clippy -p celesta-plugin-host -p celesta-gpu-renderer --all-targets
  --locked -- -D warnings`.
- In `plugins/`: `cargo clippy -p celesta-plugin-vrm --all-targets --locked
  -- -D warnings` and `cargo test -p celesta-plugin-vrm --locked`.
