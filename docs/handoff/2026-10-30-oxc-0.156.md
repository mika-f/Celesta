# oxc 0.156 upgrade (2026-10-30)

## Specification and implementation

Renovate raised the `oxc_*` crates in `celesta-source-edit` from 0.154 to
0.156. oxc now stores JavaScript string values as `JSStr` (canonical WTF-8),
which can hold lone surrogates, instead of a UTF-8 `Str` with a separate
`lone_surrogates` flag. `JSStr` has no `Display`, and
`StaticPropertyName` now wraps a `JSStr`. The crate changed as follows:

- **String literals.** `StringLiteral::lone_surrogates` and
  `TemplateElement::lone_surrogates` are gone. `string_of` and the
  substitution-free template case in `shape_of` read the value with
  `JSStr::as_str()`, which is `None` for a lone surrogate. Such a literal
  still resolves as an expression, as before. A new test,
  `a_lone_surrogate_is_an_expression` in `tests/values.rs`, covers both
  forms. Making `string_of` lossy makes it fail.
- **Property names.** `static_name()` results go through
  `StaticPropertyName::into_cow_str()`, so a key with a lone surrogate counts
  as having no static name. This applies to the object-pattern keys and
  props-type members in `lift.rs`, the style-object keys in `remove.rs`, the
  scene entry keys in `scenes.rs`, and the parameter keys in `scope.rs`.
  Before, such a key became a lossy string that matched no real name. Now
  `remove.rs` declines to remove a property followed by such a key, as it
  does after a computed key.
- **Import sources and string export names.** These use
  `JSStr::display()`, which writes a lone surrogate as `\ud800`. Each import
  and import statement stays in `Module`, so statement indices and insert
  positions do not change. The escaped text never equals `PACKAGE` or an
  export name.

## Checks

On macOS (Apple M4) with `PKG_CONFIG_PATH` pointed at FFmpeg 8:

- `cargo test -p celesta-source-edit` and `cargo test -p celesta-editor`
  (652 tests) passed.
- `cargo fmt --all -- --check` and `git diff --check` passed.
- `cargo clippy -p celesta-source-edit -p celesta-editor --all-targets -- -D warnings`
  fails only on the existing `large_enum_variant` for `SourceLookup` in
  `crates/editor/src/layer_select.rs`, which
  [2026-10-29-gpui-kit-0.8.md](2026-10-29-gpui-kit-0.8.md) records. This
  upgrade does not cause it. With
  `-A clippy::large_enum_variant` it passes.
