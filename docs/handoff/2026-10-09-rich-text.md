# `<Span>` rich text (2026-10-09)

`<Span style={{ fill, fontWeight, fontFamily }}>` changes part of a text
while the whole text is shaped, measured, wrapped, and drawn as one
paragraph (issue #147). Design: `docs/superpowers/specs/2026-10-09-rich-text-design.md`;
example: `examples/rich-text/film.tsx`. Font stacks (`fontFamily: [...]`) are
#204, built on the per-range font spans added here.

- React (`packages/react/src/rich-text.ts`): `flattenTextContent(content,
  what)` turns strings, numbers, arrays, fragments, and `<Span>` into
  `{ text, colorRuns, fontRuns }` with code-point offsets; `null`,
  `undefined`, and booleans add nothing; anything else throws, including a
  component returning a span (text children are read as props, never
  mounted: the reconciler sets text content for `text`). Nested spans
  inherit per property; adjacent equal runs merge. `withTextRuns` returns
  the style itself when there are no runs, so span-free text produces the
  same scene JSON as before, and refuses to combine `style.colorRuns` with
  span fills. `<Span>` itself throws when React renders it, i.e. outside
  text content. `<Text>`, `<TextBox>`, `<TextReveal>` (runs sliced per
  line), `<Dialogue>`, `DialogueSeries` lines (`DialogueLine.text` is now
  `ReactNode`), `useTextMetrics`, `measureText`, `useFitText`, `fitText`,
  and `useTypewriter` accept rich content. `SubtitleRenderProps.content`
  is the line as written; `style` stays without runs.
- Scene: color goes to the existing `TextStyle.colorRuns`; weight and
  family go to the new internal `TextStyle.fontRuns`
  (`TextFontRun { start, end, fontWeight?, fontFamily? }`). They are
  separate because only `fontRuns` changes layout: the shaping cache key
  includes `fontRuns` and still excludes `colorRuns`, so paint-only
  changes (Code themes, animated span colors) reuse shaped text.
  `fontRuns` is not documented for direct use, so its shape can change.
- Native shaping (`crates/renderer/src/shaping.rs`): runs become
  `attrs_list.add_span` ranges per buffer line, mapped from code points to
  shaped bytes past phrase-break word joiners (`shaped_byte_offsets`,
  `font_run_spans`). Weights go through `matched_weight`, so a missing
  weight uses the nearest face; no bold is synthesized. Emoji and joiner
  spans start from the attributes in effect where they sit, or a joiner
  would split a bold run's shaping. cosmic-text 0.18 shapes an ASCII word
  in one piece when every *added* span it overlaps matches its first
  attributes, ignoring default-attribute parts, so a line with runs also
  gets a base-attribute span over the whole line.
- Baselines: cosmic-text places each line's baseline from the tallest
  glyphs on it, so a span in a taller family would move its line.
  `run_baselines` recomputes them from the glyphs outside font runs (a line
  that is all span uses the whole text's; an empty line and text entirely
  in runs keep cosmic-text's), and `rasterize` pads the image above and
  below for run glyphs that reach past the line boxes. Without font runs
  none of this runs.
- Fallback fonts: a run splits shaping, and cosmic-text picks fallback fonts
  per shaped piece. Without `lang`, a piece next to a run can fall back to a
  different font than the whole phrase did (in an English locale, は moved
  from PingFang SC to Hiragino Sans), which changes its glyphs and can move
  the baseline; the macOS CI runner hit this. With the text's language,
  fallback follows it on both sides of the run
  (`with_a_language_runs_leave_their_neighbors_fallback_fonts_alone`), so
  `text.md` asks for `lang` on CJK text with spans.
- Warnings: `font_fallback` and `missing_glyphs` now return `Vec`s, one
  entry per family and weight a glyph asks for (the text's or its run's).
- Validation: `validate_font_runs` (ordered, non-overlapping, within the
  code points) runs in `rasterize` and in the bridge's measure request;
  shaping skips rejected runs instead of panicking.
- Browser (`packages/web`): `measureLine` measures each run piece with
  `cssFont(style, run)` and keeps the text's own font box for the
  baseline; wrapping takes that width. Styled lines build the SVG measuring
  element with one `<tspan>` per run first; `runSegments` then cuts each
  run piece where its clusters stop sitting next to each other on the
  shaped line (bidi reordering), and each segment is drawn left to right at
  its left edge or right to left (`direction: 'rtl'`) at its right edge.
  `getExtentOfChar` across tspans was checked in Chromium.
  Kerning at run edges and subpixel edge resampling differ from native.
  `cssFont` quotes family names, so generic names (`monospace`) are not
  generic families there, as before for `fontFamily`.
