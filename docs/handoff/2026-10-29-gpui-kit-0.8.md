# gpui-kit 0.8 upgrade (2026-10-29)

## Specification and implementation

Renovate raised `gpui-kit` from 0.6 to 0.8 (0.8.1, on `gpui-pre` 0.3.10). The
editor needed these changes to build and start:

- **Overlay layers.** `Root` now mounts the component layer's dialog, sheet,
  and notification layers itself through a `RootPlugin`, and
  `Root::render_dialog_layer` / `render_notification_layer` are gone. The
  editor view no longer mounts them. They still sit outside the
  `CelestaEditor` key context, so editor shortcuts stay inactive inside an
  overlay. Upstream now draws notifications above dialogs; before, the editor
  drew dialogs on top.
- **Native preview surface.** `gpui_kit::surface` takes the `objc2`
  `CFRetained<CVPixelBuffer>` instead of the `core-video` crate's type.
  `NativePreviewFrame::pixel_buffer` in `celesta-gpu-renderer` now returns that
  handle, retaining the same CoreFoundation object. The renderer keeps
  `core-video` internally and adds `objc2-core-foundation` and
  `objc2-core-video` 0.3.2, the versions GPUI uses, so the types match.
- **`secondary-` keybindings.** `KeyBinding::new` takes explicit modifiers only,
  and it panics at startup on `secondary-`. A `secondary!` macro in `main.rs`
  expands to `cmd-` on macOS and `ctrl-` elsewhere.
- **`Keystroke::parse`** takes `&'static str`, so the property-control test
  closure now takes `&'static str`.
- **Renames.** `ScrollWheelEvent` is now `ScrollEvent`, and `on_scroll_wheel`
  is now `on_scroll`.

## Checks

On macOS (Apple M4) with `PKG_CONFIG_PATH` pointed at FFmpeg 8:

- `cargo clippy --workspace --all-targets --locked -- -D warnings -A clippy::large_enum_variant`
  passed. Without the `-A`, `SourceLookup` in `crates/editor/src/layer_select.rs`
  fails `large_enum_variant`. That type does not depend on GPUI, and CI does not
  run clippy, so this upgrade did not cause the failure.
- `cargo fmt --all -- --check` and `git diff --check` passed.
- `cargo nextest run -p celesta-editor -p celesta-editor-theme -p celesta-gpu-renderer`:
  910 passed and 1 skipped. The native preview test
  (`keeps_native_preview_backings_alive_across_dialogue_frame_churn`) ran.
- Ran `celesta-editor packages/cli/examples/title.tsx` from this branch and from
  `main`. Both show the same window with the Metal preview. A temporary,
  uncommitted probe opened the Create New Project dialog at startup, and the
  two builds render it the same way. A toast also rendered through the new
  layer. This session could not send keyboard input to the app, so the
  shortcuts were not pressed. Before the macro, the app panicked when it
  bound `secondary-n`; with the macro, it starts.
