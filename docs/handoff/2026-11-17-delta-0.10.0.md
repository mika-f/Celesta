# DELTA 0.10.0, a release film from v0.9.0 to v0.10.0 (2026-11-17)

`examples/delta/film-0.10.0.tsx`: what changed between the v0.9.0 and
v0.10.0 tags, as the next film in the DELTA series. 84 s, 1920×1080, 30 fps,
cut to a 120 BPM score from `make-score-0.10.0.py` (the series' own grid in
`components/theme.ts`: a beat is 15 frames, a bar 60).

## Specification

- The release as a modular rack ("PATCH"): 0.10.0 moved what Celesta did
  inside itself out into plugins, so the features are modules patched into a
  rack. The open (4 bars) draws the rails and empty slots and powers the core
  up; seats the fourteen modules and MORE one a sixteenth; shows the title
  while the cables go in one a sixteenth, each module lighting as its input
  lands; and dives into the first module (`diveCamera`). Each feature is then
  a page: label, headline, diff and a rack map on the left, the module's
  faceplate on the right (header and run LED, the demo on its screen, the
  chapter's sentence lit word by word on the strip under it with
  `CaptionTrack`, jacks), the name on a `LowerThird`. The input cable plugs in
  on frame 8 and the LED lights; the output cable plugs in near the end.
  Pages cut on the downbeat behind a faceplate sliding across the frame in
  the incoming block's color. MORE is twelve cards of two beats. The outro
  holds the end card for a bar inside the core's screen, pulls back onto the
  rack (`pullCamera`), and powers the modules down one a sixteenth on the last
  bar; the last frame is the `poster` composition.
- Features, in four blocks with their cable colors: CONTENT (orange) CONTENT
  PLUGINS (#643 #646 #742), 3D SCENES (#668 #762 #745), VRM (#668 #655 #763),
  APPROVALS (#653 #761 #766 #730); MEDIA (blue) MEDIA PLUGINS (#681 #785
  #826), NATIVE CODECS (#799 #801 #803), PIPELINE (#775 #793 #769); REGISTRY
  (green) REGISTRY (#831 #832 #836 #849), CELESTA PLUGIN (#833 #847 #858),
  LOCK (#832 #858 #848), FIND PLUGINS (#850); EDITOR (violet) INSPECTOR (#805
  #802 #812), TIMELINE (#808 #755 #752), EXPORT PAGE (#813 #795 #736). MORE:
  X264, BT.709, STILLS, PRESETS, @CELESTA.STUDIO, CRATES.IO, FONT FACE,
  INSTANCES, EDIT GAPS, NAN, TOOLING, FIXES.
- The PR list (`v0.10.0/prs.ts`) is every PR merged between the two tags (the
  `(#n)` of `git log v0.9.0..v0.10.0 --first-parent`) except the 47 Renovate
  opened (117 PRs), titles from `gh pr list`. `COMMITS` is
  `git rev-list --count v0.9.0..v0.10.0` (1379).
- The film uses what it shows: CONTENT PLUGINS, APPROVALS and their rack
  slots draw real `<Flag>` layers and 3D SCENES a real `<Turntable>`, from
  `examples/plugins` (so the export takes `--plugin-dir ../plugins/dist`);
  every diff is highlighted by the registry plugin `code`, which the project
  locks; the MP4 goes through the media plugins (`ffmpeg/mp4`,
  `avfoundation/h264`, `ffmpeg/aac` on macOS) and is tagged BT.709; the
  poster is `builtin/jpeg`.

## Implementation notes

- `v0.10.0/module.tsx`: the faceplate (`MODULE` 1048×860 at (820, 112),
  `SCREEN`/`STAGE` 1000×563 like 0.9.0's monitor, so demos draw into the same
  stage), `Jack`, `Led`, and `Cable` (a cubic from the plug with a dark
  sleeve). `v0.10.0/rack.tsx`: sixteen slots in two rows of eight, the core
  first and MORE last, each the faceplate at `K` = 210/1048; the cable from
  slot 7 runs back along the gap between the rows. `cameraOnto` grows the
  scale geometrically, so the dive and the pull keep one speed.
- The rack's modules run their demos with `live: false`; the first holds
  frame 0 through the dive, as its page starts there.
- VRM has no model in the repository, so its demo draws a bust; its hair is
  verlet chains stepped at 60 Hz from time 0, as the plugin's spring bones
  are, so any frame comes out the same.
- Values copied from elsewhere, to update together: MEDIA PLUGINS' list
  (`--list-components` with `plugins/dist`), CELESTA PLUGIN's output (the
  registry's search and `crates/cli/src/commands/project.rs`), REGISTRY's key
  and expiry (`docs/handoff/2026-11-15-official-root-key.md`), LOCK's and
  REGISTRY's hashes (`examples/delta/celesta.lock`), NATIVE CODECS' and
  EXPORT PAGE's components (the film's export report).
- `scripts/typecheck-examples.mjs` now copies the module source of a sample
  plugin an example imports (`@celesta-plugin/<id>` with
  `examples/plugins/<id>/plugin.json`) into `.celesta/plugins/<id>/`, as it
  copies a declared registry plugin's declarations. No build is needed: tsc
  checks the plugin's `js/index.ts`.
- Celesta 0.10.0 bug found on the way: an entry passed as a bare file name
  (`Celesta-export film-0.10.0.tsx …` from its folder) leaves a plugin
  layer's asset path relative, and the flag plugin's process cannot read it
  (`could not read ../assets/…`). `./film-0.10.0.tsx`, a path with a
  directory, or an absolute path works; `package.json`'s scripts use
  `./film-0.10.0.tsx`.

## Checks

- `node scripts/typecheck-examples.mjs delta` passes.
- `inspect.mjs examples/delta/film-0.10.0.tsx` with `CELESTA_PLUGIN_PATH`
  naming `examples/plugins/dist` and `plugins/dist` evaluates frames 0, 150,
  239, 240, 300, 1000, 1960, 2100, 2400 and 2519.
- Stills of every chapter, MORE card, the open and the outro, and a contact
  sheet of the MP4 at one frame a second were checked by eye.
- The full export with a source-built `celesta-exporter` (FFmpeg 8 plugin,
  AVFoundation plugin) writes the MP4 (2520 frames, H.264 tagged BT.709 for
  primaries, transfer and matrix, AAC 48 kHz), and ja/en SRT and WebVTT (17
  cues each). `--loudness streaming`: integrated -14.0 LUFS, true peak
  -3.61 dBTP, gain -2.14 dB. The decoded audio sits at about -13.5 dBFS RMS
  per bar through the pages, -21 in the REGISTRY breakdown, and falls away
  over the last two bars.
- Not made: a 9:16 short, as 0.9.0 and earlier have.
