# gpui-kit 0.11 upgrade (2026-11-28)

## Specification and implementation

Renovate's PR #863 raised only the `gpui` dev-dependency (`gpui-pre`) from
`=0.3.11` to `=0.3.14`, and its lockfile update failed. `gpui-kit` pins
`gpui-pre` exactly, and the dev-dependency must name that same version:

| `gpui-kit` | `gpui-pre` it pins |
| ---------- | ------------------ |
| 0.9.0      | `=0.3.11`          |
| 0.9.1      | `=0.3.12`          |
| 0.10.0     | `=0.3.12`          |
| 0.11.0     | `=0.3.14`          |

So this change raises `gpui-kit` from 0.9 to 0.11 in `crates/editor` and
`crates/editor-theme`, and the `gpui` dev-dependency to `=0.3.14` in both.
When Renovate next proposes a `gpui-pre` version, raise `gpui-kit` to the
release that pins it in the same change.

The editor needed no source changes to build.

Lockfile effects:

- `gpui-kit` 0.11 adds the `gpui-fast-*` 0.1.19 crates, `jiff` 1.0, and drops
  `lyon`.
- `gpui-fast-wgpu` pins `wgpu = "=30.0.1"`, so `wgpu` moves down from 30.0.2 to
  30.0.1. `celesta-gpu-renderer` asks for `30.0.1`, so one `wgpu` remains in
  the graph.

## Checks

On macOS (Apple M4) with `PKG_CONFIG_PATH` pointed at FFmpeg 8:

- `cargo clippy -p celesta-editor -p celesta-editor-theme -p celesta-gpu-renderer --all-targets --locked -- -D warnings`
  passed. The `block` 0.1.6 future-incompatibility warning comes from
  `celesta-gpu-renderer`'s `core-video` and `metal`, and is on `main` too.
- `cargo nextest run -p celesta-editor -p celesta-editor-theme -p celesta-gpu-renderer --locked`:
  1484 passed and 2 skipped. The native preview test
  (`keeps_native_preview_backings_alive_across_dialogue_frame_churn`) ran.
- `cargo fmt --all -- --check` passed.
- Not checked here: Linux and Windows builds, which CI covers. The app was not
  started from this session, so there are no before and after screenshots of
  the editor yet.
