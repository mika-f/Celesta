# Decode YUV A/B switch

## Specification and implementation

`CELESTA_DECODE_YUV=0` makes `MediaBackend` offer RGBA8 only, regardless of
`with_accepted_pixel_formats`. Unset or any other value preserves the existing
offer, including its mandatory RGBA8 fallback. The builder reads the OS-string
environment value, like the decode prefetch switch. Both sequential and ordinary
decodes use the resulting offer. Conversion, encoding and pixel gates are unchanged.

The unit test injects the setting without mutating process-global environment.
It covers unset, exactly `0`, other values including empty and `00`, full YUV
offers, missing RGBA8, RGBA8-only and empty offers. The main YUV handoff, both
language guides and plugin skill document the switch.

## Build and checks

This box needed its existing Node/pnpm and native FFmpeg prefixes loaded, and
the absent JS dependencies installed:

```sh
export PATH="/home/ubuntu/research/node-v26.13.0-linux-x64/bin:/home/ubuntu/.nvm/versions/node/v24.22.2/bin:$PATH"
export PKG_CONFIG_PATH=/home/ubuntu/research/ffmpeg8-standard/lib/pkgconfig
export FFMPEG_X264_PKG_CONFIG_PATH=/home/ubuntu/research/ffmpeg8-x264/lib/pkgconfig
pnpm install --frozen-lockfile
pnpm run build:runtime
node scripts/plugins/build.mts plugins/ffmpeg plugins/ffmpeg-x264 plugins/avfoundation plugins/mediafoundation
cargo build --release -p celesta-exporter
```

The plugin build script creates `plugins/dist/<id>` with manifests, licenses and
release executables. This builds FFmpeg plus the optional x264 encoder, needed
for this H.264 export on Linux; AVFoundation and MediaFoundation are skipped by
their platform gates. No `--distribution` build or binaries are committed.

Exports used the blueprint software Vulkan driver, not a hardware GPU:

```sh
export VK_ICD_FILENAMES=/usr/share/vulkan/icd.d/lvp_icd.x86_64.json
export XDG_RUNTIME_DIR=/tmp
unset CELESTA_DECODE_YUV
time cargo run --release -p celesta-exporter -- --react --plugin-dir plugins/dist ./examples/greenscreen/composite.tsx --overwrite /tmp/gs.mp4
time env CELESTA_DECODE_YUV=0 cargo run --release -p celesta-exporter -- --react --plugin-dir plugins/dist ./examples/greenscreen/composite.tsx --overwrite /tmp/gs.mp4
```

Both exited 0 and printed `export complete: /tmp/gs.mp4` after 90/90 frames.
The release build was warmed before either measurement, and no other builds or
tests were running during them. One run per mode is a smoke check, not a speedup
claim or a hardware-GPU benchmark.
