## 映像と一緒に音を確認

再生時は映像と音声が同期します。波形とトラックレベルでタイミングを確認し、ミュートやソロで音を切り分け、プレビュー音量を調整できます。タイムラインの目盛りをドラッグすると好きな時点に移動でき、トラックの上で横にスワイプすると再生位置を前後に動かせます。トラックの上でピンチするとタイムラインを拡大・縮小でき、Option（Alt）を押しながらスクロールすると表示位置を動かせます。

## デバッグ用のガイド

`<DebugOverlay />` はセーフエリアの枠、その外側の網掛け、中心を描画し、`<DebugBounds>` はレイヤーのグループに枠を付けます。どちらも Celesta のプレビューと、`--debug-guides` を付けて書き出した PNG フレームやコンタクトシートに描かれ、動画には含まれないので、作業中は残しておけます。`useDebugGuides()` で自作コンポーネントもガイドを描くかどうか判定できます。

## レイヤーのソースを探す

ビューアの下にある **Safe areas** の隣のポインターのボタン、**View → Select Layers**、または `V` で **Select layers** をオンにします。このインタラクティブモードは React コンポジションを開いているときに使えます。各要素を書いた位置と各レイヤーを描いた範囲を記録するため、レイヤーが数千あるシーンでは重くなります。そのためプレビューはこのモードをオフにした状態で始まります。そうしたシーンを本来の速さで再生したいときは、オフに戻してください。切り替えるとコンポジションのランタイムを起動し直すので、少し時間がかかります。

インタラクティブモードでプレビュー上のレイヤーをクリックすると選択され、オレンジ色の枠で示されます。**React Preview** の隣にある **Properties** タブの先頭には、それが何かを示すヘッダーが表示されます。要素の種類を表すアイコン、`Rect` のようなタグ、そして自作のコンポーネントの中に書かれている要素なら、そのコンポーネント名を添えた **in `<Title>`** です。タグの下にある要素の位置（たとえば `Title.tsx:12`）をクリックすると、テキストエディタで開きます。ヘッダーの残りの部分には、レイヤーがどこに現れ、編集すると何が変わるかが表示されます（後述します）。

タブの一番下にある **Layer** セクションには、レイヤーの ID が表示されます。**Source chain** を開くと、記述されている場所がわかります。**Source** は、レイヤーにもっとも近い要素（たとえば `Title.tsx` の `<Rect>`）を、名前と `ファイル:行:列` で示します。**Called from** には、その外側の要素が近い順に並びます（たとえば、レイヤーを描画する `<Title>` や、それを囲む `<Sequence>`）。どの行もクリックすると、その位置をテキストエディタで開きます。キャンバスの何もない場所をクリックすると、選択を解除できます。

レイヤーは、描画される矩形の内側ならどこでも選べます。画像の透明な部分や、文字と文字のすき間も含みます。ただし、塗りがなく線だけの `<Rect>` は線の上でだけ選べるので、枠の内側にあるレイヤーも選べます。レイヤーが重なっている場所では、最後に描画されるものが選ばれます。表示中のフレームにないレイヤーは **Not in this frame** と表示されます。Celesta の外でファイルを編集したことによる再読み込みや、インタラクティブモードをオフにしたときは、選択が解除されます。キャンバス、プロパティの行、props ファイルの **Properties** セクションから Celesta 自身が書き込んだ変更や、元に戻す・やり直しでは、選択は保たれます。その再読み込みのあいだも、タブはヘッダーに小さなスピナーを出してレイヤーを表示し続け、再読み込みしたコンポジションがレイヤーを描き直すまでプロパティの行は読み取り専用になります。

位置は、環境変数 `VISUAL`、なければ `EDITOR` で指定したエディタで開きます。`code -n` のように引数を含められます。macOS と Linux では、Dock や Finder からアプリを起動した場合のようにアプリが変数を持っていないとき、Celesta はログインシェルにも値を問い合わせるので、シェルのプロファイルで設定した変数も使えます。VS Code（`code`）、Cursor、Windsurf、Zed、Sublime Text、JetBrains 製 IDE、TextMate は行と列まで指定して開き、そのほかのエディタには `+行 ファイル` を渡します。どちらも設定されていなければ、OS の既定のアプリケーションでファイルを開きます。この場合、位置は指定されません。

`vim`、`nano`、`emacs -nw` のように端末の中で動くエディタは、アプリから起動できません。代わりにメッセージが表示されるので、`VISUAL` にグラフィカルなエディタを指定してください。

## 編集で何が変わるかを確かめる

1 か所に書いた要素が、何か所にも描かれることがあります。いくつものシーンで使うコンポーネントは、それぞれのシーンに自分の要素を描きますし、`.map()` の中の要素は項目ごとに描かれます。そうしたレイヤーの 1 つを動かすとほかも動くので、ヘッダーには、選択したレイヤーがどこに現れ、同じ要素がほかにどこで描かれているかが表示されます。これを知るために、Celesta はインタラクティブモードをオンにしたときと、オンのあいだの再読み込みのたびに、コンポジション全体をフレームごとにバックグラウンドで調べます。この走査は別のランタイムで動くので、そのあいだもプレビューは止まりません。長いコンポジションでは少し時間がかかります。Celesta 自身の編集のあとは、新しい走査が終わるまで、ヘッダーとタイムラインは前回の走査の結果を表示し続けます。

シーンは、`<Composition>` の `chapters` で宣言したチャプターです。シーンの中に並べたパートはそのシーンとして数えるので、1 つのシーンの 2 つのパートに現れる要素は共有されているとはみなしません。現在のシーンは、再生ヘッドの位置にあるチャプターです。

- **Appears in** には、選択したレイヤーが画面に現れるシーンが並びます。チャプターのないコンポジションでは、代わりに `00:00:02:00–00:00:04:00` のような時間の範囲が並びます。範囲が 4 つ以上あるときは、最初の 3 つのあとに **and 2397 more** のように残りの数を示します。
- **Shared** は、同じ要素がほかのシーンにも描かれているときに、**also in Intro, Outro (3 instances)** のように警告色で表示されます。ほかのシーンが 4 つ以上あるときは、名前の代わりに **also in 11 other scenes (71 instances)** のように数を示します。コードが要素を描画する場所（たとえば、書いた `<Title>` の 1 つ 1 つ）が、それぞれ 1 つのインスタンスです。この行にポインタを合わせると、各インスタンスを描画している `ファイル:行:列` の一覧が表示されます。数だけを示しているときは、その前にシーンの名前が並びます。
- **Can't move** には、ロックされたトランスフォームの prop とその理由が、理由ごとに 1 行ずつ並びます（たとえば **X, Y — Written as an expression: W / 2**）。理由の意味は次の節で説明します。

プロパティのセクションの上にある 1 行は、変更を確定すると何が変わるかを示します。

| 表示 | 意味 |
| --- | --- |
| Changes this scene only | 要素が描かれるのは 1 か所だけで、ほかのシーンにはない |
| Changes `<count>` places in this scene | 要素が現在のシーンの複数の場所に描かれていて（2 つの `<Title>` や `.map()` など）、ほかのシーンにはない。`<MotionBlur>` や `<Trail>` が描く各時点のコピーは 1 か所と数える |
| Also changes `<scenes>` | 要素が、名前を挙げたシーンにも描かれている。警告色で表示される。再生ヘッドがチャプターのあいだにあるときは、要素が現れるすべてのシーンが挙がる。シーンが 4 つ以上あるときは **Also changes 11 other scenes** のように数を示し、この行にポインタを合わせるとシーンの名前が並ぶ |
| Scanning scenes… | 走査がまだ終わっていない |
| Couldn't scan scenes: `<error>` | 走査中に、あるフレームでコンポジションが失敗した。プレビューのほかの部分はそのまま使える |
| Not found in the scene scan | 走査でこの要素が見つからなかった（ソースの位置がない場合など） |

`x`、`y`、`rotation`、`scale`（または `scaleX` と `scaleY`）がすべてコンポーネントの prop で、呼び出し側で指定されているとき（次の節を参照）は、変更はその呼び出しにだけ書き込まれるので、その呼び出しが描画するインスタンスだけを数えます。ロックされた prop は関係ありません。`const PriceTag = ({ x = 0, y = 0, rotation = 0, scale = 1 }) => <Rect x={x} y={y} rotation={rotation} scale={scale} />` を Intro と Price で使っていて、`<PriceTag x={40} />` と呼び出している Price で選択すると、**Changes this scene only** と表示されます。動かして書き込まれるのはその呼び出しで、Intro の呼び出しは変わらないためです。どれか 1 つでも要素自身に書かれているか、`({ x }) => <Rect x={x} />` のように要素に書かれていないと、変更が要素に書き込まれることがあり、要素はすべてのインスタンスが描くので、すべてのインスタンスを数えます。**Shared** の行とタイムラインの帯も、この行と同じインスタンスを数えます。

タイムラインの **Composition** の行には、要素が描かれる範囲が示されます。現在のシーンで選択したレイヤーが描かれる範囲は塗りつぶしの帯、編集するとほかに変わる範囲は枠だけの帯です。帯にポインタを合わせると、シーン（チャプターのないコンポジションではタイムコード）、フレーム、そのインスタンスを描画している位置が表示され、クリックするとその最初のフレームへ移動します。同じインスタンスの帯どうしが現在のズームで 1 ピクセル未満しか離れていないときは 1 本にまとめて描かれ、その帯のツールチップにまとめた範囲の数が表示されます。**Chapters** の行では、選択したレイヤーが現れるチャプターに下線が付きます。走査が終わるまでは、レイヤーのシーケンスがレイヤーを描けるフレームの範囲が、塗りつぶしの帯 1 本で示されます。

## キャンバス上でレイヤーを動かす

インタラクティブモードで選択したレイヤーは、移動、回転、拡大・縮小ができ、結果はソースに書き戻されます。枠の内側をドラッグすると移動し、角や辺の四角いハンドルをドラッグするとアンカーを中心に拡大・縮小し、上辺の上にあるハンドルをドラッグすると回転します（Shift を押すと 15° ごとに吸着します）。**Properties** タブのヘッダーの下にある **Transform** の行に値を入力し、Enter を押すかフィールドを離れても変更できます。タブのすべての行については次の節で説明します。1 回のドラッグ、または確定した 1 つのフィールドが、2 つのファイルに書き込む場合でも 1 回の変更になります。Celesta は変更する数値だけを置き換え、書式やコメントはそのまま残します。再読み込みしても選択は保たれます。

Celesta が値を書き込むのは、ファイルに直接書かれた要素、またはその要素を書いたコンポーネントの呼び出しで、ソースが値をそのまま示している場合だけです。

- `x={80}` や `rotation={-12}` のような数値は置き換えます。
- 書かれていない prop は追加します。たとえば `x` のない `<Rect>` には `x={140}` を書き足します。
- `interpolate(frame, [0, 30, 60], [100, 600, 300])` のように書かれた prop は、指定したキーフレーム（たとえば 30）のフレームでなら編集でき、対応する出力値を変更します。フレームは、要素を書いた場所で `frame` が持つ値です。`useCurrentFrame()` の呼び出しと要素のあいだにある `<Sequence>` ではずれません。キーフレームの間ではフィールドは読み取り専用になり、**Between keyframes at 0 and 30** と、そこへ移動するボタンが表示されます。キーフレームを新しく挿入することはありません。
- 1 つの要素だけが使う `const x = 80` は、宣言している場所を置き換えます。
- `const PriceTag = ({ x }) => <Rect x={x} />` の `x` のようなコンポーネントの prop は、`<PriceTag x={40} />` のようにコンポーネントを呼び出している場所に、ここまでと同じ規則で書き込みます。呼び出しにその prop がなく、引数にデフォルト値（`{ x = 0 }`）があるときは、呼び出しに prop を書き足します。名前を変えた prop（`{ x: left }`）や `props.x` もたどります。

値がコンポーネントの呼び出し側で指定されている行には、フィールドの下に矢印と **Set at `<file>`:`<line>`**（たとえば **Set at scenes/price.tsx:12**）が表示されます。ファイルはエントリファイルのフォルダからの相対パスです。レイヤーをドラッグしたり、その行に値を入力したりすると、その呼び出しに書き込みます。呼び出しは要素とは別のファイルにあることもあります。1 回のドラッグで、呼び出し側の `x` と要素に書かれた `rotation` のように 2 つのファイルに書き込むこともありますが、それでも 1 回の変更で、1 回元に戻せば両方のファイルが戻ります。呼び出しごとに別々に編集するので、何か所からも呼び出すコンポーネントの中の要素でも、値が呼び出し側で指定されていれば、複数回描画されることを理由にロックされることはありません。`.map()` の中の呼び出しで渡した値も編集でき、変更はその呼び出しが描くすべてのコピーに及びます。

それ以外はロックされます。フィールドに鍵のアイコンと理由が表示され、ヘッダーの **Can't move** の行にも並び、レイヤーのどの値も動かせないときは枠が破線になります。理由は次のとおりです。`<name>` のように山かっこで囲んだ語は、ソースから取った部分を表します。

| 理由 | 意味 |
| --- | --- |
| Set by a component, not written on this element | レイヤーにもっとも近い要素が、`<Rect>` のような Celesta の要素ではなく、自作（またはほかのライブラリ）のコンポーネント |
| Written as an expression: `<expression>` | `W / 2` や `i * 24` のような式。または、**Anchor Y** の行の `anchorY="baseline"` のように、行が受け付けるのとは別の種類の値 |
| Comes from `<name>`, which can't be traced | import、`let`、内側のコンポーネントから読んだ外側のコンポーネントの引数、オブジェクトのプロパティ、またはコンポーネントの中で 2 回以上宣言された名前（ブロックやループの中での再宣言など） |
| Comes from `<component>`'s caller | 呼び出し側が、自分の受け取った prop をそのまま渡している（`Card` の中の `<PriceTag x={x} />` など）。Celesta がたどる呼び出しは 1 つだけで、その呼び出しの呼び出しまではたどらない |
| Can't find where `<component>` is called | 値はコンポーネントの prop だが、このレイヤーを描画している呼び出しが見つからない、またはそのファイルを読めない |
| `<name>` is used in `<count>` places | 共有されている `const` を編集すると、ほかの要素も動いてしまう |
| Between keyframes at `<frame>` and `<frame>` | キーフレームのフレームではない。ボタンでキーフレームへ移動できる |
| Outside the keyframes | 最初のキーフレームより前、または最後のキーフレームより後のフレーム |
| Computed by `<function>`() | `spring()` のような関数の呼び出し |
| A layout component sets this value | 要素が受け取った値が書かれた値と違う。レイアウトコンポーネントなどの親が値を置き換えている |
| May be set by a spread ({...props}) | 要素に `{...props}` があり、その要素自身には値がない。または値の後ろにスプレッドがある |
| May be set by `style` | `<Text>` のフォントや色の行で、`style` がオブジェクトとして書かれていない、または値を指定しうるスプレッドがある（次の節を参照） |
| Rendered `<count>` times from this element | `.map()` の中の要素で、編集すると全部のコピーが動いてしまう |
| Can't tell which frame this animation reads | `frame` が複数のフレームのどれかを持ちうる（要素を囲む `<Sequence>` や `<FreezeFrame>` ごとに別のフレームになる）うえ、それらのフレームが同じ値の別々のキーフレームを指している |
| This file is outside the project | 値が、エントリファイルのフォルダの外にあるファイル、または `node_modules` の中に書かれている。要素のファイルか、呼び出し側で指定された値なら呼び出しのファイル |
| Couldn't find this element in the source | プレビューが見つけた位置に、ファイルの要素がもうない（保存後の再読み込み中など） |
| The source has syntax errors | 先にファイルを直してください。解析できるまで、すべてのフィールドがロックされます |

ドラッグ中に、ドラッグが書き込むファイルが変更された場合、Celesta はドラッグを破棄してその旨を表示し、あなたの編集を上書きすることはありません。キャンバスでのドラッグで編集するのは `x`、`y`、`rotation`、`scale`（`scaleX` と `scaleY` が書かれているときはそちら）だけです。`width` のようなサイズの prop やアンカーは、次の節で説明するとおり **Properties** タブで編集します。スキューは編集できません。

`<Group>` や `<Stack>` の中のレイヤーは、親と一緒に動きます。`<Stack>` の子も編集でき、その `x` と `y` は `<Stack>` が割り当てた位置からのずれになります。**Source chain** の中の **Called from** の行のうち、`<Group>` のように自分のレイヤーを描く Celesta の要素の行には **Select** ボタンがあり、そのレイヤーを選択できます。グループは子要素をすべて囲む矩形で示され、その内側のどこをドラッグしてもグループ全体が動きます。`<Stack>` や `<SafeArea>` の行には **Select** ボタンがありません。これらはコンポーネントで、作るグループはソースに書かれていないためです。

## プロパティを編集する

**Properties** タブのヘッダーの下には、選択した要素の prop がセクションに分かれて、要素が宣言している順に 1 行ずつ並びます。どの Celesta の要素も、最初のセクションは **Transform** です。X、Y、Rotation、Scale（ソースに `scaleX` か `scaleY` が書かれているときは、代わりに Scale X と Scale Y）、Anchor X、Anchor Y、Opacity が並びます。それより後のセクションは要素によって変わります。

| 要素 | Transform の後のセクション |
| --- | --- |
| `<Rect>` | **Size**（Width、Height、Corner radius）、**Appearance**（Fill、Stroke、Stroke width） |
| `<Text>` | **Text**（Text、Font family、Font size、Font weight、Color）、**Layout**（Max width） |
| `<Image>` | **Source**（Source）、**Size**（Width、Height、Fit） |
| `<Video>` | **Source**（Source、Start from、Playback rate、Loop）、**Audio**（Volume、Muted） |
| `<Group>` | なし（**Transform** だけ） |
| `<Ellipse>`、`<Heart>` | **Size**（Width、Height）、**Appearance**（Fill、Stroke、Stroke width） |
| `<Circle>` | **Size**（Radius）、`<Ellipse>` と同じ **Appearance** |
| `<Triangle>` | **Size**（Width、Height、Apex、Corner radius）、`<Ellipse>` と同じ **Appearance** |
| `<Polygon>` | **Size**（Radius、Sides、Corner radius）、`<Ellipse>` と同じ **Appearance** |
| `<Star>` | **Size**（Radius、Points、Inner ratio、Corner radius）、`<Ellipse>` と同じ **Appearance** |
| `<Pie>` | **Size**（Radius、Start angle、End angle、Corner radius）、`<Ellipse>` と同じ **Appearance** |

`<Path>`、`<Line>`、`<Arrow>`、`<Mask>` のようなそのほかの要素では、**Transform** に X、Y、Rotation、Scale（または Scale X と Scale Y）だけが並びます。

各行は、前の節の規則に従い、ソースが値をそのまま示している場所に prop を書き込みます。要素自身、コンポーネントの呼び出し（その行には **Set at `<file>`:`<line>`** が表示されます）、1 つの要素だけが使う `const` のいずれかです。文字列、`true` と `false`、`<Text>` のテキストも数値と同じように書き込み、文字列は書かれていた引用符のまま残します。それ以外は、キャンバスと同じく理由を添えてロックされます。ソースに書かれていない prop は、描画に使われている値を薄く表示します。その prop がコンポーネントの引数ならそのデフォルト値、そうでなければレイヤーが受け取った値、または要素自身のデフォルト値です。値を入力すると、その prop を書き足します。

各行には、値の種類に応じたコントロールがあります。

| 値 | コントロール | 書き込むとき |
| --- | --- | --- |
| 数値 | フィールド。行のラベルをドラッグすると値を連続して変えられる | Enter を押すかフィールドを離れたとき、またはラベルを離したとき |
| テキスト（`<Text>` の **Text** の行） | 複数行に広がるフィールド | Enter を押すかフィールドを離れたとき。Shift+Enter で改行する |
| 文字列（**Font family** など） | フィールド | Enter を押すかフィールドを離れたとき |
| オン・オフ（**Loop** など） | スイッチ | すぐに |
| 選択肢のどれか（**Fit** など） | メニュー | すぐに |
| 色 | フィールドと、ピッカーを開く色見本 | Enter を押すかフィールドを離れたとき、またはピッカーを閉じたとき |
| ファイル（**Source** など） | フィールドと **Choose…**、**None** | Enter を押すかフィールドを離れたとき、またはファイルを選んだとき |

フィールドで Escape を押すと、ソースの値に戻ります。数値の行に入力した単語や、prop の範囲外の数値のように、行が受け付けない値は、行の下にメッセージが表示され、書き込まれません。**Opacity** は 0 から 1、**Font weight** は 1 から 1000 です。サイズ、半径、線の幅、**Font size**、**Max width**、ビデオの **Start from**、**Playback rate**、**Volume** は 0 以上、画像の **Width** と **Height** は 1 以上、図形の **Stroke width** は 0.1 以上、**Sides** と **Points** は 3 以上の整数です。色は `#RRGGBB`、`#RRGGBBAA`、または `accent` のような `<Theme>` の色の名前で、入力したとおりに書き込みます。名前の場合、色見本には色が表示されません。`fit="fill"` のように、選択肢にない値がソースに書かれているメニューは、別の選択肢を選ぶまでその値を表示します。**Choose…** は、ファイルのパスをエントリファイルのフォルダからの相対パスで書き込みます。そのフォルダの外にあるファイルは、先にフォルダの中の `assets` フォルダにコピーします。**None** は、書かれているパスを空のパスに書き換え、prop が書かれていないときは何も書き込みません。

ソースに書かれた prop を取り除いてデフォルト値に戻すには、フィールドを空にして Enter を押す（またはフィールドを離れる）か、行にポインタを重ねて、行の端の **×** をクリックします。スイッチやメニューの行にも **×** があります。要素の属性、`style={{ … }}` のプロパティ、**Set at** の付いた行では呼び出し側の属性が取り除かれ、コンポーネントのデフォルト値が使われるようになります。そのあと行には、その prop なしで描かれる値が薄く表示されます。`<Rect>` の **Width** と **Height**、`<Image>` の **Source**、`<Text>` の **Text** のように要素に欠かせない prop には **×** がなく、フィールドを空にしても値が戻ります。ソースに書かれていない prop、ロックされた行、キーフレームでアニメーションする行、入力の行（後述）も同じです。

Celesta が値を書き込んで再読み込みしているあいだも、行は編集できます。入力していたフィールドにはキーボードのフォーカスが残り、そのまま入力を続けられます。そのあいだに確定した値は、再読み込みが終わってから書き込みます。フィールドを離れると、その値は確定します。ほかのレイヤーを選んだとき、プレビューの何もないところをクリックしたとき、再生位置を動かしたとき、再生を始めたときも同じで、入力した値は Enter を押したときと同じように書き込み、行が受け付けない値は捨てます。再読み込みを待っている値があるときは、その値を書き込んでから新しい選択を表示します。コードの再読み込みに失敗したときは、待っていた値は書き込まず、その行に **Not saved: the code failed to reload** と表示します。

数値は、ラベルを左右にドラッグして変えられます。1 ピクセルごとに prop のステップだけ変わります。**Scale**、**Scale X**、**Scale Y**、**Anchor X**、**Anchor Y** と、ビデオの **Playback rate** と **Volume** のステップは 0.01、**Font weight** のステップは 100 です（フォントの書体は 100 刻みの太さで用意されています）。コンポーネントの prop では、`registerComponent()` のスキーマに書いた `step` がステップになります。ステップのない prop は、**Opacity** のように範囲の上限が 1 以下なら 0.01 ずつ、それ以外は 1 ずつ変わります。Shift を押していると 1 回の変化が 10 倍になります。値は prop の範囲で止まります。ソースに書かれていない prop は、行に薄く表示されている値から変わり始めます。ドラッグしているあいだも、同じ値から描かれるほかのレイヤーを含めてプレビューが追従し、値はマウスを離したときに 1 回だけ書き込みます。離す前に Escape を押すと、何も書き込まずにすべて元に戻ります。動かさずに、または元の値に戻して離したときも何も書き込みません。ドラッグした行に入力していたテキストは、ドラッグした値に置き換わります。ほかの行に入力してまだ確定していないテキストはそのフィールドに残り、キーボードのフォーカスもそこに残ります。そうでないときはラベルを押すとフォーカスがフィールドから離れるので、ドラッグの直後に `⌘ Z`（`Ctrl Z`）を押すとそのドラッグを元に戻せます。ロックされた行、キーフレームでアニメーションする行、入力の行（後述）は、ラベルをドラッグしても変わらず、再生中はどのラベルもドラッグで値を変えられません。キャンバスでのレイヤーのドラッグとラベルのドラッグは同時には行えず、一方を始めると、もう一方は何も書き込まずに終わります。

`width={textWidth + padding * 2}` のようにほかの値から計算される値はロックされたままで、式が読む名前が、その行の下に字下げされた入力の行として並びます（この例では **textWidth** と **padding**）。各入力は同じ規則でたどるので、1 つの要素だけが使う `const` や、呼び出し側で指定されたコンポーネントの prop（自身の **Set at** の行が付きます）は、その行で編集できます。それ以外の入力には、ロックの理由が表示されます。入力は 1 段だけで、それ自体が式である入力は展開しません。`<PriceTag x={left + 8} />` のように、コンポーネントの呼び出し側で計算される値には、入力の行は並びません。

`<Text>` の **Font family**、**Font size**、**Font weight**、**Color** の行は、`style` に従います。これらの prop より `style` が優先されるためです。`style={{ … }}` がその値（**Color** では `fill`）を指定しているときは、行はそこを編集します。そうでなければ prop 自体を編集し、値を指定していない `style` の隣に `fontSize={48}` のように書き足します。`style={mono(20)}` のように `style` がオブジェクトとして書かれていないときや、`style` の中や要素にあるスプレッドが値を指定しうるときは、**May be set by `style`** としてロックされます。

要素が自作のコンポーネントの中に書かれていて、Celesta がそれを描画している呼び出しを見つけたときは、続いて **Component · PriceTag** のような **Component** セクションが表示され、その呼び出しの **Set at `<file>`:`<line>`** が添えられます。このセクションには、呼び出しに書かれた prop が書かれた順に並ぶので、`<PriceTag>` の中の `<Rect>` を選択したまま、`<PriceTag>` の `label="Sale"` を変更できます。上の行がすでに **Set at** 付きで表示している prop は繰り返さず、`key`、`ref`、スプレッド、子要素は並びません。数値には数値のフィールド、文字列にはテキストのフィールド、`true` か `false` にはスイッチが付きます。コンポーネントが `registerComponent()` で登録されているときは、代わりにそのスキーマがコントロールと範囲を決め、スキーマと別の種類の値はロックされます。値をそのまま示していない prop は、理由を添えてロックされます。

影響を示す行と **Can't move** が見るのは、トランスフォームの prop だけです。**Fill** のように要素に書かれたほかの prop を編集すると、その行が 1 つの呼び出しのインスタンスだけを数えていても、すべてのインスタンスが変わります。呼び出し側で指定された値（**Set at** の付いた行や **Component** セクションの行）を編集したときは、その呼び出しだけが変わります。

## 元に戻す

元に戻す（`⌘ Z`、`Ctrl Z`）とやり直し（`⌘ Shift Z`、`Ctrl Shift Z`）で、Celesta が書き込んだ変更を順にたどれます。キャンバス、プロパティの行、props ファイルの **Properties** セクションのどれからの変更も、同じ履歴に最大 100 件まで残り、別のファイルを開くと消えます。確定した 1 つの行、スイッチ、メニューの選択、ピッカーで選んだ色、選んだファイル、ラベルのドラッグ、取り除いた prop が、それぞれ 1 回の変更です。コンポーネントの呼び出し側とコンポーネントのように 2 つのファイルに書き込んだ変更も、1 回で元に戻し、1 回でやり直します。変更のあとに、変更が書き込んだファイルがほかの場所で編集されていた場合、Celesta はあなたの編集を上書きしないよう元に戻すのを断り、どちらのファイルも変更しません。
