**File → Open…** で React コンポジション（`.tsx`、`.jsx`、`.ts`、`.js`）を開きます。素材、トラック、クリップを選ぶと、Inspector で詳細を確認できます。

> [!NOTE]
> **ソースがキャンバス**
> コンポジションはテキストエディタで編集します。Celesta でプレビューと書き出しを行い、ソースを保存すると表示が更新されます。

ソースを保存すると自動で再読み込みされます。**File → Reload** で手動更新することもできます。

## 映像と一緒に音を確認

再生時は映像と音声が同期します。波形とトラックレベルでタイミングを確認し、ミュートやソロで音を切り分け、プレビュー音量を調整できます。タイムラインの目盛りをドラッグすると好きな時点に移動でき、トラックの上で横にスワイプすると再生位置を前後に動かせます。トラックの上でピンチするとタイムラインを拡大・縮小でき、Option（Alt）を押しながらスクロールすると表示位置を動かせます。

## デバッグ用のガイド

`<DebugOverlay />` はセーフエリアの枠、その外側の網掛け、中心を描画し、`<DebugBounds>` はレイヤーのグループに枠を付けます。どちらも Celesta のプレビューと、`--debug-guides` を付けて書き出した PNG フレームやコンタクトシートに描かれ、動画には含まれないので、作業中は残しておけます。`useDebugGuides()` で自作コンポーネントもガイドを描くかどうか判定できます。

## レイヤーのソースを探す

ビューアの下にある **Safe areas** の隣のポインターのボタン、**View → Select Layers**、または `V` で **Select layers** をオンにします。このインタラクティブモードは React コンポジションを開いているときに使えます。各要素を書いた位置と各レイヤーを描いた範囲を記録するため、レイヤーが数千あるシーンでは重くなります。そのためプレビューはこのモードをオフにした状態で始まります。そうしたシーンを本来の速さで再生したいときは、オフに戻してください。切り替えるとコンポジションのランタイムを起動し直すので、少し時間がかかります。

インタラクティブモードでプレビュー上のレイヤーをクリックすると選択され、オレンジ色の枠で示されます。**React Preview** の隣にある **Properties** タブの先頭には、それが何かを示すヘッダーが表示されます。要素の種類を表すアイコン、`Rect` のようなタグ、そして自作のコンポーネントの中に書かれている要素なら、そのコンポーネント名を添えた **in `<Title>`** です。タグの下にある要素の位置（たとえば `Title.tsx:12`）をクリックすると、テキストエディタで開きます。ヘッダーの残りの部分には、レイヤーがどこに現れ、編集すると何が変わるかが表示されます（後述します）。

タブの一番下にある **Layer** セクションには、レイヤーの ID が表示されます。**Source chain** を開くと、記述されている場所がわかります。**Source** は、レイヤーにもっとも近い要素（たとえば `Title.tsx` の `<Rect>`）を、名前と `ファイル:行:列` で示します。**Called from** には、その外側の要素が近い順に並びます（たとえば、レイヤーを描画する `<Title>` や、それを囲む `<Sequence>`）。どの行もクリックすると、その位置をテキストエディタで開きます。キャンバスの何もない場所をクリックすると、選択を解除できます。

レイヤーは、描画される矩形の内側ならどこでも選べます。画像の透明な部分や、文字と文字のすき間も含みます。ただし、塗りがなく線だけの `<Rect>` は線の上でだけ選べるので、枠の内側にあるレイヤーも選べます。レイヤーが重なっている場所では、最後に描画されるものが選ばれます。表示中のフレームにないレイヤーは **Not in this frame** と表示されます。Celesta の外でファイルを編集したことによる再読み込みや、インタラクティブモードをオフにしたときは、選択が解除されます。キャンバス、プロパティの行、props ファイルの **Properties** セクションから Celesta 自身が書き込んだ変更や、元に戻す・やり直しでは、選択は保たれます。その再読み込みのあいだも、タブはヘッダーに小さなスピナーを出してレイヤーを表示し続け、再読み込みしたコンポジションがレイヤーを描き直すまでプロパティの行は読み取り専用になります。

位置は、環境変数 `VISUAL`、なければ `EDITOR` で指定したエディタで開きます。`code -n` のように引数を含められます。macOS と Linux では、Dock や Finder からアプリを起動した場合のようにアプリが変数を持っていないとき、Celesta はログインシェルにも値を問い合わせるので、シェルのプロファイルで設定した変数も使えます。VS Code（`code`）、Cursor、Windsurf、Zed、Sublime Text、JetBrains 製 IDE、TextMate は行と列まで指定して開き、そのほかのエディタには `+行 ファイル` を渡します。どちらも設定されていなければ、OS の既定のアプリケーションでファイルを開きます。この場合、位置は指定されません。

`vim`、`nano`、`emacs -nw` のように端末の中で動くエディタは、アプリから起動できません。代わりにメッセージが表示されるので、`VISUAL` にグラフィカルなエディタを指定してください。

## 編集で何が変わるかを確かめる

1 か所に書いた要素が、何か所にも描かれることがあります。いくつものシーンで使うコンポーネントは、それぞれのシーンに自分の要素を描きますし、`.map()` の中の要素は項目ごとに描かれます。そうしたレイヤーの 1 つを動かすとほかも動くので、ヘッダーには、選択したレイヤーがどこに現れ、同じ要素がほかにどこで描かれているかが表示されます。これを知るために、Celesta はインタラクティブモードをオンにしたときと、オンのあいだの再読み込みのたびに、コンポジション全体をフレームごとにバックグラウンドで調べます。この走査は別のランタイムで動くので、そのあいだもプレビューは止まりません。長いコンポジションでは少し時間がかかります。Celesta 自身の編集のあとは、新しい走査が終わるまで、ヘッダーとタイムラインは前回の走査の結果を表示し続けます。

シーンは、`<Composition>` の `chapters` で宣言したチャプターです。シーンの中に並べたパートはそのシーンとして数えるので、1 つのシーンの 2 つのパートに現れる要素は共有されているとはみなしません。現在のシーンは、再生ヘッドの位置にあるチャプターです。

- **Appears in** には、選択したレイヤーが画面に現れるシーンが並びます。チャプターのないコンポジションでは、代わりに `00:00:02:00–00:00:04:00` のような時間の範囲が並びます。範囲が 4 つ以上あるときは、最初の 3 つのあとに **and 2397 more** のように残りの数を示します。
- **Shared** は、同じ要素がほかのシーンにも描かれているときに、**also in Intro, Outro (3 instances)** のように警告色で表示されます。ほかのシーンが 4 つ以上あるときは、名前の代わりに **also in 11 other scenes (71 instances)** のように数を示します。コードが要素を描画する場所（たとえば、書いた `<Title>` の 1 つ 1 つ）が、それぞれ 1 つのインスタンスです。この行にポインタを合わせると、各インスタンスを描画している `ファイル:行:列` の一覧が表示されます。数だけを示しているときは、その前にシーンの名前が並びます。**Edits change** に選択肢が表示されているあいだ（「1 つのシーンだけを変えるか、すべてのシーンを変えるか」を参照）は、選んだ選択肢がほかのシーンを変えないときも、この行は消えずに **this scene only** と表示されます。
- **Can't move** には、ロックされたトランスフォームの prop とその理由が、理由ごとに 1 行ずつ並びます（たとえば **X, Y — Written as an expression: W / 2**）。理由の意味は次の節で説明します。

パネルのいちばん上、ヘッダーの上にある 1 行は、変更を確定すると何が変わるかを示します。この行はその位置にとどまり、ヘッダーとプロパティのセクションはその下でスクロールします。共有されている要素では、代わりに編集が何を変えるかを選ぶコントロールが表示されます。後述の「1 つのシーンだけを変えるか、すべてのシーンを変えるか」を参照してください。

| 表示 | 意味 |
| --- | --- |
| Changes this scene only | 要素が描かれるのは 1 か所だけで、ほかのシーンにはない |
| Changes `<count>` places in this scene | 要素が現在のシーンの複数の場所に描かれていて（2 つの `<Title>` や `.map()` など）、ほかのシーンにはない。`<MotionBlur>` や `<Trail>` が描く各時点のコピーは 1 か所と数える |
| Also changes `<scenes>` | 要素が、名前を挙げたシーンにも描かれている。警告色で表示される。再生ヘッドがチャプターのあいだにあるときは、要素が現れるすべてのシーンが挙がる。シーンが 4 つ以上あるときは **Also changes 11 other scenes** のように数を示し、この行にポインタを合わせるとシーンの名前が並ぶ |
| Scanning scenes… | 走査がまだ終わっていない |
| Couldn't scan scenes: `<error>` | 走査中に、あるフレームでコンポジションが失敗した。プレビューのほかの部分はそのまま使える |
| Not found in the scene scan | 走査でこの要素が見つからなかった（ソースの位置がない場合など） |

この行が表示されるのは、共有されていない要素です。つまり、インスタンスが 1 つだけの要素か、自作のコンポーネントの中ではなくシーンに直接書かれた要素です。自作のコンポーネントの中に書かれていてインスタンスが 2 つ以上ある要素（たとえば、Intro と Price で使う `const PriceTag = ({ label }) => <Rect width={200} … />` の `<Rect>`）は共有されています。その場合は代わりに **Edits change** と、**This scene** と **Shared value** の 2 つの選択肢が表示され、**Shared** の行とタイムラインの帯は、選んでいる選択肢で変わるインスタンスを数えます。

タイムラインの **Composition** の行には、要素が描かれる範囲が示されます。現在のシーンで選択したレイヤーが描かれる範囲は塗りつぶしの帯、編集するとほかに変わる範囲は枠だけの帯です。帯にポインタを合わせると、シーン（チャプターのないコンポジションではタイムコード）、フレーム、そのインスタンスを描画している位置が表示され、クリックするとその最初のフレームへ移動します。同じインスタンスの帯どうしが現在のズームで 1 ピクセル未満しか離れていないときは 1 本にまとめて描かれ、その帯のツールチップにまとめた範囲の数が表示されます。**Chapters** の行では、選択したレイヤーが現れるチャプターに下線が付きます。走査が終わるまでは、レイヤーのシーケンスがレイヤーを描けるフレームの範囲が、塗りつぶしの帯 1 本で示されます。再生ヘッドの位置の塗りつぶしの帯では、グリップか **Set timing** ボタンで要素のタイミングを変えられ、チャプターの終わりではそのシーンの長さを変えられます。後述の「タイムラインでタイミングを変える」を参照してください。

## キャンバス上でレイヤーを動かす

インタラクティブモードで選択したレイヤーは、移動、回転、サイズの変更、拡大・縮小ができ、結果はソースに書き戻されます。枠の内側をドラッグすると移動し、角や辺の四角いハンドルをドラッグするとサイズが変わり（**Scale** のハンドルでは拡大・縮小します）、上辺の上にあるハンドルをドラッグすると回転します（Shift を押すと 15° ごとに吸着します）。回転と拡大・縮小は、**Center** を選ばないかぎりレイヤーのピボットを軸にします。詳しくはこの節の最後で説明します。**Properties** タブのヘッダーの下にある **Transform** の行に値を入力し、Enter を押すかフィールドを離れても変更できます。タブのすべての行については次の節で説明します。1 回のドラッグ、または確定した 1 つのフィールドが、2 つのファイルに書き込む場合でも 1 回の変更になります。Celesta は変更する数値だけを置き換え、書式やコメントはそのまま残します。再読み込みしても選択は保たれます。

Celesta が値を書き込むのは、ファイルに直接書かれた要素、またはその要素を書いたコンポーネントの呼び出しで、ソースが値をそのまま示している場合だけです。

- `x={80}` や `rotation={-12}` のような数値は置き換えます。
- 書かれていない prop は追加します。たとえば `x` のない `<Rect>` には `x={140}` を書き足します。
- `interpolate(frame, [0, 30, 60], [100, 600, 300])` のように書かれた prop は、指定したキーフレーム（たとえば 30）のフレームでなら編集でき、対応する出力値を変更します。フレームは、要素を書いた場所で `frame` が持つ値です。`useCurrentFrame()` の呼び出しと要素のあいだにある `<Sequence>` ではずれません。キーフレームの間ではフィールドは読み取り専用になり、**Between keyframes at 0 and 30** と、そこへ移動するボタンが表示されます。キーフレームを新しく挿入することはありません。
- 1 つの要素だけが使う `const x = 80` は、宣言している場所を置き換えます。
- `const PriceTag = ({ x }) => <Rect x={x} />` の `x` のようなコンポーネントの prop は、`<PriceTag x={40} />` のようにコンポーネントを呼び出している場所に、ここまでと同じ規則で書き込みます。呼び出しにその prop がなく、引数にデフォルト値（`{ x = 0 }`）があるときは、呼び出しに prop を書き足します。名前を変えた prop（`{ x: left }`）や `props.x` もたどります。

値がコンポーネントの呼び出し側で指定されている行には、フィールドの下に矢印と **Set at `<file>`:`<line>`**（たとえば **Set at scenes/price.tsx:12**）が表示されます。ファイルはエントリファイルのフォルダからの相対パスです。レイヤーをドラッグしたり、その行に値を入力したりすると、その呼び出しに書き込みます。呼び出しは要素とは別のファイルにあることもあります。1 回のドラッグで、呼び出し側の `x` と要素に書かれた `rotation` のように 2 つのファイルに書き込むこともありますが、それでも 1 回の変更で、1 回元に戻せば両方のファイルが戻ります。呼び出しごとに別々に編集するので、何か所からも呼び出すコンポーネントの中の要素でも、値が呼び出し側で指定されていれば、複数回描画されることを理由にロックされることはありません。`.map()` の中の呼び出しで渡した値も編集でき、変更はその呼び出しが描くすべてのコピーに及びます。

それ以外はロックされます。フィールドに鍵のアイコンと理由が表示され、ヘッダーの **Can't move** の行にも並び、レイヤーのどの値も動かせないときは枠が破線になります。理由は次のとおりです。`<name>` のように山かっこで囲んだ語は、ソースから取った部分を表します。

| 理由 | 意味 |
| --- | --- |
| Set by a component, not written on this element | レイヤーにもっとも近い要素が、`<Rect>` のような Celesta の要素ではなく、自作（またはほかのライブラリ）のコンポーネント |
| Written as an expression: `<expression>` | `W / 2` や `i * 24` のような式。または、**Anchor Y** の行の `anchorY="baseline"` のように、行が受け付けるのとは別の種類の値 |
| Comes from `<name>`, which can't be traced | import、`let`、内側のコンポーネントから読んだ外側のコンポーネントの引数、オブジェクトのプロパティ、またはコンポーネントの中で 2 回以上宣言された名前（ブロックやループの中での再宣言など） |
| Comes from `<component>`'s caller | 呼び出し側が、自分の受け取った prop をそのまま渡している（`Card` の中の `<PriceTag x={x} />` など）。Celesta がたどる呼び出しは 1 つだけで、その呼び出しの呼び出しまではたどらない |
| Can't find where `<component>` is called | 値はコンポーネントの prop だが、このレイヤーを描画している呼び出しが見つからない、またはそのファイルを読めない |
| `<name>` is used in `<count>` places | 共有されている `const` を編集すると、ほかの要素も動いてしまう |
| Between keyframes at `<frame>` and `<frame>` | キーフレームのフレームではない。ボタンでキーフレームへ移動できる |
| Outside the keyframes | 最初のキーフレームより前、または最後のキーフレームより後のフレーム |
| Computed by `<function>`() | `spring()` のような関数の呼び出し |
| A layout component sets this value | 要素が受け取った値が書かれた値と違う。レイアウトコンポーネントなどの親が値を置き換えている |
| May be set by a spread ({...props}) | 要素に `{...props}` があり、その要素自身には値がない。または値の後ろにスプレッドがある |
| May be set by `style` | `<Text>` のフォントや色の行で、`style` がオブジェクトとして書かれていない、または値を指定しうるスプレッドがある（次の節を参照） |
| Rendered `<count>` times from this element | `.map()` の中の要素、またはフレームに 2 回以上描かれる自作コンポーネントの中の要素で、編集すると全部のコピーが動いてしまう。コンポーネントの場合は、そのコピーを描画する呼び出しがそれだけを描いていれば、**This scene** で選んだコピーだけを動かせる（「1 つのシーンだけを変えるか、すべてのシーンを変えるか」を参照） |
| Can't tell which frame this animation reads | `frame` が複数のフレームのどれかを持ちうる（要素を囲む `<Sequence>` や `<FreezeFrame>` ごとに別のフレームになる）うえ、それらのフレームが同じ値の別々のキーフレームを指している |
| This file is outside the project | 値が、エントリファイルのフォルダの外にあるファイル、または `node_modules` の中に書かれている。要素のファイルか、呼び出し側で指定された値なら呼び出しのファイル |
| Couldn't find this element in the source | プレビューが見つけた位置に、ファイルの要素がもうない（保存後の再読み込み中など） |
| The source has syntax errors | 先にファイルを直してください。解析できるまで、すべてのフィールドがロックされます |

ドラッグ中に、ドラッグが書き込むファイルが変更された場合、Celesta はドラッグを破棄してその旨を表示し、あなたの編集を上書きすることはありません。キャンバスでのドラッグで編集するのは、`x`、`y`、`rotation`、`scale`（`scaleX` と `scaleY` が書かれているときはそちら）と、`width` のようなレイヤーのサイズを決める prop、`anchorX` と `anchorY` です。サイズの prop とアンカーについてはこの節の最後で説明します。スキューは編集できません。

`<Group>` や `<Stack>` の中のレイヤーは、親と一緒に動きます。`<Stack>` の子も編集でき、その `x` と `y` は `<Stack>` が割り当てた位置からのずれになります。**Source chain** の中の **Called from** の行のうち、`<Group>` のように自分のレイヤーを描く Celesta の要素の行には **Select** ボタンがあり、そのレイヤーを選択できます。グループは子要素をすべて囲む矩形で示され、その内側のどこをドラッグしてもグループ全体が動きます。`<Stack>` や `<SafeArea>` の行には **Select** ボタンがありません。これらはコンポーネントで、作るグループはソースに書かれていないためです。

### 中心とピボットのどちらを軸にするか

**Select layers** がオンのあいだは、ビューアの上端、フレームの上にツールの行が表示されます（フレームはその分だけ小さくなります）。行の先頭には **Add** メニューがあります（後述の「キャンバスに要素を追加する」を参照）。レイヤーを選択しているあいだは、その後ろにラベルの付いた 2 つの切り替えが並びます。それぞれの切り替えでは、選んだほうが浮き出たタブで示されます。1 つ目の **Rotate about** [**Center** | **Pivot**] は、回転のハンドルと **Scale** のハンドルが何を軸にするかを決めます。選択したレイヤーの上の十字が、その点を示します。

- **Pivot**（既定）は、レイヤーのピボット、つまりレンダラーがレイヤーを回す点を軸にします。ピボットはアンカー（矩形に対する `anchorX` と `anchorY` の位置で、指定しなければ左上の角）を、`originX` と `originY` を指定していればその分だけずらした点です。書き込むのは `rotation` か拡大率だけです。十字はピボットの上にあり、Alt を押しながらドラッグするとアンカーが動きます（後述の「アンカーを動かす」を参照）。
- **Center** は、レイヤーの矩形の中心をその場に保ちます。そのために、Celesta は `x` と `y` も書き込みます。回転では `rotation`、`x`、`y` をまとめて 1 回の変更として書き込み、`x` と `y` がコンポーネントの呼び出しから渡されていれば 2 つのファイルに書き込みます。十字は矩形の中心の上にあり、その点を示すだけです。ツールチップには **Rotates about the center; switch to Pivot to move the anchor** と表示されます（**Pivot** でもアンカーを動かせないときは、**Rotates about the center; the anchor can't move:** に続けて、「アンカーを動かす」で挙げる理由が表示されます。`<Path>` のようにアンカーの prop がない要素では、**Rotates about the center** だけが表示されます）。Alt を押しながら押しても何も起きません。

**Center** には、Celesta が書き込める `x` と `y` が必要です。それぞれ数値か、書かれていない prop か、上で説明したようにコンポーネントの呼び出しから渡された値です。`rotation`、拡大率、サイズ、アンカーがキーフレームでアニメーションしていないことも必要です。あるキーフレームで書き込んだ `x` と `y` では、そのキーフレームでしか中心を保てず、ほかのキーフレームではレイヤーがずれるためです。これを満たさないレイヤーは、**Center** を選んでいてもピボットを軸にし、十字もピボットの上に表示されます。そのとき切り替えは **Center** が選ばれたまま残るので、次に選択したレイヤーではまた **Center** が使われます。切り替えには警告のアイコンが表示され、そのツールチップに理由が表示されます。

| ツールチップ | 意味 |
| --- | --- |
| x or y can't be edited | `x` か `y` がキーフレームでアニメーションしているか、コードで計算した値のようにロックされている |
| Rotation or scale is animated | `rotation` か拡大率がキーフレームでアニメーションしている |
| Size or anchor is animated | サイズの prop、`anchorX`、`anchorY` のどれかがキーフレームでアニメーションしている |
| No flat box to center on | レイヤー自身の遠近法で傾いている |

同じ理由は、回転のハンドルや **Scale** のハンドルにポインタを合わせたときと、それらをドラッグしているあいだのレイヤーの横にも、**Pivot —** に続けて表示されます。

### Size のハンドルでサイズを変える

2 つ目の切り替えの **Handles** [**Size** | **Scale**] は、角と辺のハンドルが何をするかを決めます。**Size**（既定）では、ハンドルはレイヤーのサイズを決める prop を変え、ドラッグした辺や角の反対側はその場に残ります。これは **Center** と **Pivot** のどちらを選んでいても同じです。

| 要素 | ハンドル | 書き込む prop |
| --- | --- | --- |
| `<Rect>`、`<Image>`、`<Video>`、`<Ellipse>`、`<Triangle>`、`<Heart>` | 4 つの角と 4 つの辺。辺は 1 辺の長さを、角は両方を変える | `width`、`height` |
| `<Circle>`、`<Polygon>`、`<Star>`、`<Pie>` | 4 つの角。縦横を同じ比率で変える | `radius` |
| `<Text>` | 左右の辺 | `maxWidth` |

ハンドルはそれらの prop が表す矩形の上にあり、その矩形が選択の枠として描かれます。ハンドルはレイヤーの回転、拡大率、スキューに沿います。ドラッグはレイヤー自身の軸に沿って測ります。角をドラッグするときに Shift を押していると、矩形の縦横比が保たれます。`<Text>` の矩形はレイアウトの矩形です。辺をドラッグすると、`maxWidth` が書かれていればその幅から、なければいちばん長い行の幅から始まり、テキストを新しい幅で折り返し、`maxWidth` を整数のピクセルで書き込みます。`maxWidth` が書かれていなければ書き足します。`width` か `height` を書いていない `<Image>` や `<Video>` は、その辺を絵の縦横比から決めます。もう一方の辺をドラッグすると、書いていない辺を現在の長さのまま書き込むので、変わるのはドラッグした辺だけです。

その場に残る辺がアンカーの位置にないとき（たとえば、左上の角をアンカーにしたレイヤーの左辺と上辺）は、その辺を残すために Celesta は `x` と `y` も書き込みます。そのためには **Center** と同じく、Celesta が書き込める `x` と `y` と、キーフレームでアニメーションしていない `rotation`、拡大率、アンカーが必要で、そうでないときはそれらのハンドルが表示されません。サイズは prop の範囲（たとえば画像の **Width** は 1 以上）で止まり、1 ピクセルより小さくはならないので、辺を反対側の辺の先までドラッグしても矩形が裏返ることはありません。キーフレームでアニメーションするサイズは、行と同じように、キーフレームのフレームでならサイズを変えられます。ただし、そのサイズの向きにアンカーを動かすハンドルは表示されません。そうしたハンドルが書き込む `x` と `y` では、そのキーフレームでしか辺を残せないためです。その向きにアンカーを動かさないハンドルは使えます。たとえば、左上の角をアンカーにしたレイヤーの `width` がアニメーションしているときは、左辺と左側の 2 つの角が表示されず、右辺、上辺と下辺、右側の 2 つの角は使えます。

`<Group>` や `<Path>` のようにサイズの prop がない要素や、サイズを書き込めない要素では、代わりに **Scale** のハンドルが表示されます。切り替えは **Size** が選ばれたまま残り、次のレイヤーではまた使われます。切り替えには警告のアイコンが表示され、そのツールチップに理由が表示されます。

| ツールチップ | 意味 |
| --- | --- |
| No size to resize | 要素にサイズの prop がない、またはプレビューがサイズを伝えていない |
| `<Row>`: `<reason>` | サイズの行がロックされている（たとえば **Height: Written as an expression: h * 2**）。理由は上の表のとおり |
| Size can't be edited here | サイズの prop に、Celesta が書き込める行がない |
| x or y can't move | どのハンドルもアンカーを動かすことになり、`x` か `y` がキーフレームでアニメーションしているか、ロックされている |
| Rotation or scale is animated | どのハンドルもアンカーを動かすことになり、`rotation` か拡大率がキーフレームでアニメーションしている |
| Anchor is animated | どのハンドルもアンカーを動かすことになり、`anchorX` か `anchorY` がキーフレームでアニメーションしている |
| Size is animated | どのハンドルも、キーフレームでアニメーションするサイズの向きにアンカーを動かすことになる |
| No flat box to resize | レイヤー自身の遠近法で傾いている |

**Scale** では、角と辺のハンドルはレイヤーを拡大・縮小し、`scale`（ソースに `scaleX` か `scaleY` が書かれているときは `scaleX` と `scaleY`）を書き込みます。回転のハンドルは、どちらのツールでも同じように使えます。

### アンカーを動かす

**Pivot** が効いているときは、選択したレイヤーのピボットに十字が表示されます。Alt（Option）を押しながら十字をドラッグすると、アンカーが動きます。Celesta は `anchorX` と `anchorY` をレイヤーの矩形に対する割合（左端や上端が 0、右端や下端が 1。矩形の外の値もそのまま使えます）で書き込み、`x` と `y` を十字と同じだけ動かすので、画面上のレイヤーは動きません。ここでの矩形は、アンカーが基準にする矩形です。`<Text>` ではレイアウトの矩形、図形では `width` × `height`（`<Circle>` では `radius` の 2 倍）、画像やビデオでは描かれる画像の範囲です。Alt を押しているあいだは、十字の上のポインタが開いた手の形になり、十字がハンドルと重なっていても十字が優先されます。**Center** と同じく、アンカーを動かすには Celesta が書き込める `x` と `y` が必要です。アンカー、`rotation`、拡大率、サイズがキーフレームでアニメーションしていないことも必要です。そのあとの回転は、新しいアンカーを軸にします。**Center** が効いているときは、十字は矩形の中心を示すだけでアンカーは動かせません。アンカーを動かすには **Pivot** を選んでください。

十字をドラッグできないときは、Alt を押しながら十字にポインタを合わせると禁止の形になり、十字にポインタを合わせると理由が表示されます。

| ツールチップ | 意味 |
| --- | --- |
| `<Row>`: `<reason>` | その行自身のロックの理由。たとえば、インポートした定数で `x` を指定していれば **X: Comes from DX, which can't be traced**、`anchorY="baseline"` と書いた `<Text>` では **Anchor Y: Written as an expression: "baseline"** |
| X is animated、Y is animated | `x` か `y` がキーフレームでアニメーションしている |
| Anchor is animated | `anchorX` か `anchorY` がキーフレームでアニメーションしている |
| Rotation or scale is animated | `rotation` か拡大率がキーフレームでアニメーションしている |
| Size is animated | サイズの prop がキーフレームでアニメーションしている |
| A group's anchor has no effect | `<Group>` は、子要素を自身の位置だけで配置する |
| No box to anchor in | レイヤー自身の遠近法で傾いているか、プレビューがサイズを伝えていない |

`<Path>`、`<Line>`、`<Arrow>` など、アンカーの prop がない要素には、動かせるアンカーがありません。

## プロパティを編集する

**Properties** タブのヘッダーの下には、選択した要素の prop がセクションに分かれて、要素が宣言している順に 1 行ずつ並びます。どの Celesta の要素も、最初のセクションは **Transform** です。X、Y、Rotation、Scale（ソースに `scaleX` か `scaleY` が書かれているときは、代わりに Scale X と Scale Y）、Anchor X、Anchor Y、Opacity が並びます。それより後のセクションは要素によって変わります。

| 要素 | Transform の後のセクション |
| --- | --- |
| `<Rect>` | **Size**（Width、Height、Corner radius）、**Appearance**（Fill、Stroke、Stroke width） |
| `<Text>` | **Text**（Text、Font family、Font size、Font weight、Color）、**Layout**（Max width） |
| `<Image>` | **Source**（Source）、**Size**（Width、Height、Fit） |
| `<Video>` | **Source**（Source、Start from、Playback rate、Loop）、**Size**（Width、Height）、**Audio**（Volume、Muted） |
| `<Group>` | なし（**Transform** だけ） |
| `<Ellipse>`、`<Heart>` | **Size**（Width、Height）、**Appearance**（Fill、Stroke、Stroke width） |
| `<Circle>` | **Size**（Radius）、`<Ellipse>` と同じ **Appearance** |
| `<Triangle>` | **Size**（Width、Height、Apex、Corner radius）、`<Ellipse>` と同じ **Appearance** |
| `<Polygon>` | **Size**（Radius、Sides、Corner radius）、`<Ellipse>` と同じ **Appearance** |
| `<Star>` | **Size**（Radius、Points、Inner ratio、Corner radius）、`<Ellipse>` と同じ **Appearance** |
| `<Pie>` | **Size**（Radius、Start angle、End angle、Corner radius）、`<Ellipse>` と同じ **Appearance** |

`<Path>`、`<Line>`、`<Arrow>`、`<Mask>` のようなそのほかの要素では、**Transform** に X、Y、Rotation、Scale（または Scale X と Scale Y）だけが並びます。

各行は、前の節の規則に従い、ソースが値をそのまま示している場所に prop を書き込みます。要素自身、コンポーネントの呼び出し（その行には **Set at `<file>`:`<line>`** が表示されます）、1 つの要素だけが使う `const` のいずれかです。文字列、`true` と `false`、`<Text>` のテキストも数値と同じように書き込み、文字列は書かれていた引用符のまま残します。それ以外は、キャンバスと同じく理由を添えてロックされます。ソースに書かれていない prop は、描画に使われている値を薄く表示します。その prop がコンポーネントの引数ならそのデフォルト値、そうでなければレイヤーが受け取った値、または要素自身のデフォルト値です。値を入力すると、その prop を書き足します。

各行には、値の種類に応じたコントロールがあります。

| 値 | コントロール | 書き込むとき |
| --- | --- | --- |
| 数値 | フィールド。行のラベルをドラッグすると値を連続して変えられる | Enter を押すかフィールドを離れたとき、またはラベルを離したとき |
| テキスト（`<Text>` の **Text** の行） | 複数行に広がるフィールド | Enter を押すかフィールドを離れたとき。Shift+Enter で改行する |
| 文字列（**Font family** など） | フィールド | Enter を押すかフィールドを離れたとき |
| オン・オフ（**Loop** など） | スイッチ | すぐに |
| 選択肢のどれか（**Fit** など） | メニュー | すぐに |
| 色 | フィールドと、ピッカーを開く色見本 | Enter を押すかフィールドを離れたとき、またはピッカーを閉じたとき |
| ファイル（**Source** など） | フィールドと **Choose…**、**None** | Enter を押すかフィールドを離れたとき、またはファイルを選んだとき |

フィールドで Escape を押すと、ソースの値に戻ります。数値の行に入力した単語や、prop の範囲外の数値のように、行が受け付けない値は、行の下にメッセージが表示され、書き込まれません。**Opacity** は 0 から 1、**Font weight** は 1 から 1000 です。サイズ、半径、線の幅、**Font size**、**Max width**、ビデオの **Start from**、**Playback rate**、**Volume** は 0 以上、画像とビデオの **Width** と **Height** は 1 以上、図形の **Stroke width** は 0.1 以上、**Sides** と **Points** は 3 以上の整数です。色は `#RRGGBB`、`#RRGGBBAA`、または `accent` のような `<Theme>` の色の名前で、入力したとおりに書き込みます。名前の場合、色見本には色が表示されません。`fit="fill"` のように、選択肢にない値がソースに書かれているメニューは、別の選択肢を選ぶまでその値を表示します。**Choose…** は、ファイルのパスをエントリファイルのフォルダからの相対パスで書き込みます。そのフォルダの外にあるファイルは、先にフォルダの中の `assets` フォルダにコピーします。**None** は、書かれているパスを空のパスに書き換え、prop が書かれていないときは何も書き込みません。

ソースに書かれた prop を取り除いてデフォルト値に戻すには、フィールドを空にして Enter を押す（またはフィールドを離れる）か、行にポインタを重ねて、行の端の **×** をクリックします。スイッチやメニューの行にも **×** があります。要素の属性、`style={{ … }}` のプロパティ、**Set at** の付いた行では呼び出し側の属性が取り除かれ、コンポーネントのデフォルト値が使われるようになります。そのあと行には、その prop なしで描かれる値が薄く表示されます。`<Rect>` の **Width** と **Height**、`<Image>` の **Source**、`<Text>` の **Text** のように要素に欠かせない prop には **×** がなく、フィールドを空にしても値が戻ります。ただし、`{ rectWidth = 200 }` に渡す `rectWidth={260}` のように、値をそのまま書いたデフォルト値のある引数に呼び出し側で指定した値は取り除けます。取り除くとデフォルト値が使われます。コンポーネントの `registerComponent()` のスキーマで `required: true` とした prop も、**Component** セクションに並ぶときも **Set at** の付いた行に表示されるときも同じです。スキーマのないコンポーネントの prop は、どれでも取り除けます。ソースに書かれていない prop、ロックされた行（現在のシーンが自分で値を指定しているためにロックされた行を除きます。「1 つのシーンだけを変えるか、すべてのシーンを変えるか」を参照）、キーフレームでアニメーションする行、入力の行（後述）も同じです。共有されている要素では、**×** が何を取り除くかは、パネルのいちばん上で選んでいる選択肢に従います。「1 つのシーンだけを変えるか、すべてのシーンを変えるか」を参照してください。

Celesta が値を書き込んで再読み込みしているあいだも、行は編集できます。入力していたフィールドにはキーボードのフォーカスが残り、そのまま入力を続けられます。そのあいだに確定した値は、再読み込みが終わってから書き込み、それまで行に **Saving…** と表示します。フィールドを離れると、その値は確定します。ほかのレイヤーを選んだとき、プレビューの何もないところをクリックしたとき、再生位置を動かしたとき、再生を始めたときも同じで、入力した値は Enter を押したときと同じように書き込み、行が受け付けない値は捨てます。再読み込みを待っている値があるときは、その値を書き込んでから新しい選択を表示します。インタラクティブモードをオフにするときも同じように待ちます。値を書き込むまで **Select layers** ボタンにはスピナーが表示され、レイヤーは選択されたままです。そのあいだにもう一度オンにすると、モードも選択もそのまま残ります。コードの再読み込みに失敗したときは、待っていた値は書き込まず、その行に **Not saved: the code failed to reload** と表示します。プレビューが予期せず止まったときは **Not saved: the preview stopped unexpectedly** と表示し、Celesta を起動し直すまで行からは値を書き込みません。

数値は、ラベルを左右にドラッグして変えられます。1 ピクセルごとに prop のステップだけ変わります。**Scale**、**Scale X**、**Scale Y**、**Anchor X**、**Anchor Y** と、ビデオの **Playback rate** と **Volume** のステップは 0.01、**Font weight** のステップは 100 です（フォントの書体は 100 刻みの太さで用意されています）。コンポーネントの prop では、`registerComponent()` のスキーマに書いた `step` がステップになります。ステップのない prop は、**Opacity** のように範囲の上限が 1 以下なら 0.01 ずつ、それ以外は 1 ずつ変わります。Shift を押していると 1 回の変化が 10 倍になります。値は prop の範囲で止まります。ソースに書かれていない prop は、行に薄く表示されている値から変わり始めます。ドラッグしているあいだも、同じ値から描かれるほかのレイヤーを含めてプレビューが追従し、値はマウスを離したときに 1 回だけ書き込みます。離す前に Escape を押すと、何も書き込まずにすべて元に戻ります。動かさずに、または元の値に戻して離したときも何も書き込みません。ドラッグした行に入力していたテキストは、ドラッグした値に置き換わります。ほかの行に入力してまだ確定していないテキストはそのフィールドに残り、キーボードのフォーカスもそこに残ります。そうでないときはラベルを押すとフォーカスがフィールドから離れるので、ドラッグの直後に `⌘ Z`（`Ctrl Z`）を押すとそのドラッグを元に戻せます。ロックされた行、キーフレームでアニメーションする行、入力の行（後述）は、ラベルをドラッグしても変わらず、再生中はどのラベルもドラッグで値を変えられません。キャンバスでのレイヤーのドラッグとラベルのドラッグは同時には行えず、一方を始めると、もう一方は何も書き込まずに終わります。

`width={textWidth + padding * 2}` のようにほかの値から計算される値はロックされたままで、式が読む名前が、その行の下に字下げされた入力の行として並びます（この例では **textWidth** と **padding**）。各入力は同じ規則でたどるので、1 つの要素だけが使う `const` や、呼び出し側で指定されたコンポーネントの prop（自身の **Set at** の行が付きます）は、その行で編集できます。それ以外の入力には、ロックの理由が表示されます。入力は 1 段だけで、それ自体が式である入力は展開しません。`<PriceTag x={left + 8} />` のように、コンポーネントの呼び出し側で計算される値には、入力の行は並びません。

`<Text>` の **Font family**、**Font size**、**Font weight**、**Color** の行は、`style` に従います。これらの prop より `style` が優先されるためです。`style={{ … }}` がその値（**Color** では `fill`）を指定しているときは、行はそこを編集します。そうでなければ prop 自体を編集し、値を指定していない `style` の隣に `fontSize={48}` のように書き足します。`style={mono(20)}` のように `style` がオブジェクトとして書かれていないときや、`style` の中や要素にあるスプレッドが値を指定しうるときは、**May be set by `style`** としてロックされます。

要素が自作のコンポーネントの中に書かれていて、Celesta がそれを描画している呼び出しを見つけたときは、続いて **Component · PriceTag** のような **Component** セクションが表示され、その呼び出しの **Set at `<file>`:`<line>`** が添えられます。このセクションには、呼び出しに書かれた prop が書かれた順に並ぶので、`<PriceTag>` の中の `<Rect>` を選択したまま、`<PriceTag>` の `label="Sale"` を変更できます。上の行がすでに **Set at** 付きで表示している prop は繰り返さず、`key`、`ref`、スプレッド、子要素は並びません。数値には数値のフィールド、文字列にはテキストのフィールド、`true` か `false` にはスイッチが付きます。コンポーネントが `registerComponent()` で登録されているときは、代わりにそのスキーマがコントロールと範囲を決め、フィールドの `label` が行の名前になり（スキーマにない prop は書かれた名前のまま表示されます）、`integer: true` の数値フィールドは整数だけを受け付け、`required: true` のフィールドは取り除けず、スキーマと別の種類の値はロックされます。`ComponentPropertySchema<BadgeProps>` のようにスキーマをprops の型で型付けしていると、props の型が必須とする prop には `required: true` を書くよう、またそれ以外には書かないよう TypeScript が求めます。値をそのまま示していない prop は、理由を添えてロックされます。

**Can't move** が見るのは、トランスフォームの prop だけです。**Component** セクションの行は常にその呼び出しに書き込むので、変わるのはその呼び出しが描画するインスタンスだけです。共有されている要素では、それ以外の行、ラベルのドラッグ、キャンバスでのドラッグ、キャンバス上でのテキストの編集は、パネルのいちばん上で選んでいる選択肢に従って書き込みます。「1 つのシーンだけを変えるか、すべてのシーンを変えるか」を参照してください。

## キャンバス上でテキストを編集する

インタラクティブモードでプレビュー上の `<Text>` をダブルクリックすると、描かれている場所でそのままテキストを編集できます。フォント、サイズ、色、折り返しはそのテキスト自身のもので、回転や反転、3D の傾きがあっても同じように編集できます。選択していないテキストは最初のクリックで選択され、Celesta がソースを読み終えたところで編集が始まります。再生中なら一時停止します。編集中はハンドルと十字が消え、枠は残ります。入力する位置はアクセントカラーの点滅しないキャレットで示され、選択範囲は同じ色で塗られます。

キーを押すたびにプレビューはテキストを描き直しますが、確定するまで何も書き込まず、そのあいだコードも実行しません。そのため、テキストに合わせた枠のように、コードがテキストから計算するものは、確定後の再読み込みまで元の大きさのままです。`visibleCharacters` で少しずつ表示するテキストは、編集中は全文を表示し、再読み込みで元の表示に戻ります。

| キー | 動作 |
| --- | --- |
| 矢印、`Home` / `End` | キャレットを動かす。Shift を押していると選択する。上下の移動では、短い行をまたいでも横の位置を保つ |
| `⌘ A`、`⌘ C`、`⌘ X`、`⌘ V`（Windows と Linux では `Ctrl`） | すべて選択、コピー、カット、ペースト。ペーストしたテキストは書式なしで、改行は通常の改行になる |
| `Shift Enter` | 改行する |
| `Enter`、`⌘ Enter` | 編集を確定する |
| `Escape` | 何も書き込まずに終える。プレビューはソースのテキストに戻る |
| `Tab`、`⌘ Z`、`⌘ Shift Z` | 編集中は何もしない。確定したあとは、1 回元に戻せば編集全体が戻る |

編集中のキー入力はテキストに届きます。`Space`、`V`、`I`、`O`、矢印は、再生や移動、モードの切り替えではなく、文字の入力やキャレットの移動になります。**File → New**、**Open…**、**Reload**、**Close**、**Export**（とそのショートカット）は先に編集を確定し、**Reload**、**Close**、終了は書き込みが終わるまで、最大 5 秒待ちます。`⌘ /`（ループ）と **Show problems** では編集は終わりません。

テキストの内側をクリックするとキャレットが動き、ドラッグすると選択し、Shift を押しながらクリックすると選択を広げます。テキストのレイアウトの矩形の外をクリックすると、編集を確定してから、そのクリックがいつもどおりに働きます。`maxWidth` のない 1 行のテキストでは矩形が最後の文字で終わるので、そのすぐ右をクリックしても外になります。**Properties** タブやツールの行など、ウインドウのほかの場所をクリックしたときも編集を確定し、キーボードのフォーカスはクリックした場所に移ります。タブの **Text** の行は編集中も使え、確定後は書き込んだテキストを表示します。ほかのレイヤーを選んだとき、選択を解除したとき、インタラクティブモードをオフにしたとき、再生位置を動かしたとき、再生を始めたときも確定します。

日本語のように入力メソッドで入力する言語も、テキストフィールドと同じように使えます。変換中のテキストは下線付きでプレビューに描かれ、候補ウインドウはキャレットの位置に開きます。変換中の 1 回目の Escape は入力メソッドに届いて変換を取り消し、2 回目で編集を終えます。変換中のまま編集を確定すると（テキストの外をクリックするなど）、表示されているとおりに書き込みます。

確定したテキストは、**Text** の行と同じように書き込みます。書き込む先は、ソースがテキストをそのまま示している JSX のテキストや文字列、1 つの要素だけが使う `const`、そして `<Label text="Sale" />` のように prop で渡されたテキストならコンポーネントの呼び出し側です。改行を含むテキストは `{"Sale\nToday"}` のような文字列として書き込みます。1 回の確定は 1 回の変更で、1 回元に戻せば戻ります。変えなかったテキストや空にしたテキストは何も書き込みません（`<Text>` にはテキストが欠かせないので、空にするとソースのテキストに戻ります）。確定後、プレビューは古いテキストをちらつかせることなく、再読み込みが描き直すまで新しいテキストを表示し続けます。ほかの値を書き込んでいる途中なら、行の確定と同じように順番を待ちます。編集を始めたあとにファイルが変わったときのように書き込みに失敗すると、プレビューはソースのテキストに戻ります。理由は、プレビューの左上（次にクリックするまで）と **Properties** タブに表示されます。

Celesta が書き込めないテキストでは、ダブルクリックしても編集は始まりません。代わりにドラッグ中のラベルと同じ見た目で理由をレイヤーの横に表示し、次にクリックするまで残します。

| 表示 | 意味 |
| --- | --- |
| **Text** の行のロックの理由（たとえば **Written as an expression: a + b**） | コードで計算した値や `<Span>` の子要素のように、テキストがソースにそのまま書かれていない。理由は「キャンバス上でレイヤーを動かす」の表のとおり |
| レイヤーのソースを読めなかった理由（たとえば **Not in this frame**） | **Layer** セクションの表示と同じ |
| The code is reloading | コンポジションを再読み込みしている。終わってからもう一度ダブルクリックする |
| The text isn't drawn in this frame | 表示中のフレームにテキストがない、またはテキストの角が視点より後ろにある |
| The text is edge-on to the view | 3D で真横近くまで傾いていて、入力できる面がない |
| The text can't be edited here | **Text** の行に、Celesta が書き込めるものがない |

確定した直後のテキストをダブルクリックすると、書き込みが終わるまで待ち、再読み込みのあいだは **The code is reloading** と表示します。再読み込みが終わってからもう一度ダブルクリックすると、新しいテキストを編集できます。編集中に Celesta の外でファイルが変わると、何も書き込まずに編集を終え、次にクリックするまでプレビューの左上に **The source changed while editing** と表示します。

## 1 つのシーンだけを変えるか、すべてのシーンを変えるか

自作のコンポーネントの中に書いた要素は、そのコンポーネントの呼び出しのすべてが描きます。選択した要素にインスタンスが 2 つ以上あるとき（たとえば、Intro、Price、Outro の各シーンで呼び出している `<PriceTag>` の中の `<Rect>`）は、確定する前に、編集でこのシーンを変えるか、シーンが共有している値を変えるかを選びます。パネルのいちばん上の 1 行が、その選択肢になります。パネルをスクロールしてもこの行は見えたままなので、下のほうの行を編集しながら選択肢を確かめたり切り替えたりできます。

```text
Edits change  [ This scene ]  [ Shared value ]
              Shared value is used in Intro, Outro · Price sets its own
```

- **This scene** は、現在のシーンのインスタンスだけに向けて編集を書き込みます。最初はこちらが選ばれています。
- **Shared value** は、自分の値を指定していないすべてのシーンが使う値を書き込みます。

選んでいる選択肢は、ビューアの上端のツールの行と同じく、浮き上がったタブで示されます。もう一方をクリックすると、そちらを選びます。Celesta は要素ごとに選択をセッションのあいだ覚えているので、背景を何度編集しても、そのたびに選び直す必要はありません。Celesta 自身の編集のあと、編集している要素は、要素の上に 1 行増えるような編集で位置が動いても選択を保ちます。その編集が書き込んだファイルのほかの要素も動いているかもしれないので、それらは最初の選択に戻ります。Celesta の外でファイルが変わったときは、すべての要素が最初の選択に戻ります。タブにポインタを重ねているあいだ、タイムラインの帯とヘッダーの **Shared** の行は、その選択肢で変わるインスタンスを示します。それ以外のときは、選んでいる選択肢で変わるインスタンスを示します。

タブの下の行は、共有の値が届くシーンと、自分の値を指定しているシーンを示します。後者は **Shared value** の編集では変わりません（**Shared value is used in Intro, Outro · Price sets its own**）。シーンでのコンポーネントの呼び出しが、要素の行が読む prop のどれかを渡していれば、そのシーンは自分の値を指定しています。そうしたシーンが複数あるときは **Price, Sale set their own** のように並び、4 つ以上あるときは **5 scenes** のように数を示します。チャプターのないコンポジションでは **Shared value is used everywhere**、すべてのシーンが自分の値を指定しているときは **Shared value is used in no scene** と表示されます。

現在のシーンがコンポーネントを 2 回以上呼び出しているとき（たとえば Price に Sale と Second の 2 つの `<PriceTag>` があるとき）は、**This scene** は選んだインスタンスの呼び出しだけに書き込み、シーンのほかの呼び出しは値を保ちます。**This scene** が選ばれているあいだ、またはそのタブにポインタを重ねているあいだ、タブの下の行は **Edits this `<PriceTag>` only · this scene calls it 2 times** となり、タイムラインの帯は選んだインスタンスだけを示します。タブのツールチップは **Write the edit for this call only** です。チャプターのないコンポジションでは、タイムライン全体が 1 つのシーンなので、タブの下の行とツールチップは呼び出しが 1 つのときと同じです。

### This scene が書き込むもの

コンポーネントが prop として受け取る値（行に **Set at** が表示される値）は、選択肢がないときと同じく、現在のシーンの呼び出しに書き込みます。それ以外の値は、コンポーネントの新しい prop に移します。今の値はその prop のデフォルト値になるのでほかのシーンはそのまま残り、新しい値はこのシーンの呼び出しで渡します。Price のシーンで **This scene** を選び、幅を 260 にした例です。

```tsx
// 変更前
function PriceTag({ label }: Props) {
  return <Rect width={200} … />;
}
// Price.tsx
<PriceTag label="Sale" />

// 変更後
function PriceTag({ label, rectWidth = 200 }: Props) {
  return <Rect width={rectWidth} … />;
}
// Price.tsx
<PriceTag label="Sale" rectWidth={260} />
```

新しい prop の名前は、要素のタグと prop の名前からつくります（`rectWidth`、`textFontSize`、`rectX` など）。コンポーネントのファイルでその名前がすでに使われているとき、またはシーンの呼び出しがその名前をすでに書いているとき（`...rest` で要素に渡している場合）は、`rectWidth2` のように番号を付けます。デフォルト値は元の値と同じ書き方で書きます（`width="200"` なら `"200"`）。引数のないコンポーネントには引数を追加し（`function PriceTag({ rectWidth = 200 })`）、引数に `...rest` があるときは、その前に新しい prop を入れます。引数の型が型リテラルか、同じファイルで宣言した `interface` や `type` のとき（`FC<Props>`、`memo<Props>`、`forwardRef<…, Props>` を通したものも含みます）は、`rectWidth?: number` のような省略可能なフィールドを追加します。要素に書かれていない prop も、Celesta がデフォルト値を知っていればそれをデフォルト値にして、同じように移します。コンポーネントの中で 1 つの要素だけが使う `const` は、新しい prop を値にします。レイヤーを動かすと、`x` と `y` を一緒に移します。この編集は 2 つのファイルに書き込むことが多いですが、それでも 1 回の変更で、1 回元に戻せば両方が戻ります。

そのあとで同じ要素をほかのシーンで編集すると、そのシーンの呼び出しに書き込み（たとえば Intro の `<PriceTag>` に `rectWidth={180}`）、コンポーネントは変わりません。

シーンがコンポーネントを 2 回以上呼び出しているときは、値は選んだインスタンスの呼び出しだけで渡します。シーンのほかの呼び出しは新しい prop を渡さないので、デフォルト値になった元の値のまま残ります。フレームに 2 回以上描かれるコンポーネントの要素に書かれた値（たとえば 2 つの値札の `x`）は、**Shared value** では **Rendered 2 times from this element** としてロックされます。そこに書き込むと全部のコピーが動いてしまうためです。**This scene** では、選んだインスタンスの呼び出しがそれだけを描いていれば、ほかの値と同じく新しい prop に移すので、キャンバスで値札の 1 つをドラッグできます。`x` と `y` はその呼び出しに移り、もう一方の値札は動きません。ドラッグしているあいだや、**X** や **Y** のラベルをドラッグしているあいだは、プレビューがすべてのコピーを新しい位置に描きます。離すと、選んだ呼び出しだけに書き込み、選んだコピーだけが動きます。その呼び出し自体が `.map()` の中などで要素を 2 回以上描いているときは、値はロックされたままです。

### Shared value が書き込むもの

要素に書かれた値は、選択肢がないときと同じくそこに書き込みます。ほかの prop で自分の値を指定しているシーンも含めて、すべてのシーンが変わります。現在のシーンの呼び出しが渡していないコンポーネントの prop の行は、**Set at** なしで、引数のデフォルト値（`{ label, rectWidth = 200 }` の `rectWidth = 200` など）を表示し、編集します。デフォルト値のない引数には、`{ label, rectWidth = 240 }` のようにデフォルト値を追加します。その行には、要素のデフォルト値が薄く表示されます。その prop を渡している呼び出しは値をそのまま保ち、タブの下の行がそのシーンを示します。自分の値を指定しているシーンが変わらないのは、こうした値だけです。要素のすべての行がコンポーネントの prop のときは、タイムラインの帯とヘッダーの **Shared** の行はそのシーンを除きます。それ以外のときは、すべてのインスタンスを示します。

現在のシーンの呼び出しがその prop を自分で渡しているとき（たとえば Price の `<PriceTag>` の `rectWidth={260}`）は、共有の値を編集してもほかのシーンが変わるだけで、このシーンは変わりません。そのため行には、プレビューが描いているこのシーンの値が、呼び出しを示す **Set at** の行とともに表示され、行は **This scene sets its own `rectWidth`** としてロックされます。その prop については、レイヤーのドラッグ、ラベルのドラッグ、キャンバス上でのテキストの編集もロックされます。呼び出しが `rectWidth={260}` のように値をそのまま書いているときは、このシーンから共有の値を編集できます。行にポインタを重ねて **×** をクリックします。ツールチップは **Use the shared value** です。呼び出しからその属性が取り除かれ、行は共有の値を表示して編集できるようになります。`rectWidth={size * 2}` のように呼び出しが計算している値や、要素に欠かせない prop で引数に値をそのまま書いたデフォルト値がないものには **×** がありません。その prop を渡していないシーンから共有の値を編集してください。このシーンの値を変えるには、代わりに **This scene** を選びます。

### 選択肢を選べないとき

編集を書き込めない選択肢は薄く表示され、タブの下の行とタブのツールチップに理由が表示されます。**This scene** を選べないときは、代わりに **Shared value** が選ばれます。次の表の理由は、`PriceTag` の `<Rect>` とその `rectWidth` の場合の表示です。実際には、あなたのコンポーネントと prop の名前が入ります。**This scene** を選べないのは、次の場合です。

| 理由 | 意味 |
| --- | --- |
| Can't find where `<PriceTag>` is called | このシーンのインスタンスを描画している呼び出しが見つからない、またはそのファイルを読めない |
| Passes through `<Card>` | シーンと、要素を書いたコンポーネントのあいだに、ここでは `<PriceTag>` を囲む `<Card>` という別の自作のコンポーネントがある。`<Sequence><PriceScene /></Sequence>` のように、コンポーネントとして書いて手で並べたシーンも、これにあたる |
| The scenes reuse the same call (`.map()` or `defineScenes`) | `defineScenes` でつくり 1 つの `<Scenes>` で描くシーンのように、1 つの呼び出しが複数のシーンのコンポーネントを描画している |
| `<PriceTag>` is called here for other scenes too | `.map()` の中の呼び出しのように、このシーンのインスタンスを描画している呼び出しが、ほかのシーンのインスタンスも描画している |
| `<PriceTag>` here draws this element more than once | このシーンがコンポーネントを 2 回以上呼び出していて、選んだインスタンスの呼び出し自体も、`.map()` の中の呼び出しのように要素を 2 回以上描いている。その呼び出しに書き込むと、それが描くすべてのコピーが変わってしまう |

次の理由は行ごとのものです。**This scene** では、その行が理由を添えてロックされ、書き込める行が 1 つもないときだけ選択肢を選べなくなります。

| 理由 | 意味 |
| --- | --- |
| `PriceTag` doesn't take its props as `{ … }` | コンポーネントの引数が `(props)` や `(...args)` のように書かれている |
| `PriceTag`'s props type is in another file | 引数の型をインポートしている |
| Can't add `rectWidth` to `PriceTag`'s props type | `type Props = Base & Other` のように、フィールドを追加する型リテラルが型にない |
| Can't be set per scene yet | 値がキーフレームでアニメーションする、`style={{ … }}` のオブジェクトの中にある、または入力の行の `const` である |
| This file is outside the project | コンポーネントのファイルか呼び出しのファイルが、エントリファイルのフォルダの外か `node_modules` の中にある |

**Shared value** では、次の場合に行がロックされ、すべての行がロックされると選択肢を選べなくなります。ただし **This scene sets its own** は行をロックするだけで、選択肢を選べなくすることはありません。

| 理由 | 意味 |
| --- | --- |
| Every scene sets `rectWidth` itself | 引数にデフォルト値がなく、すべての呼び出しがその prop を渡している |
| This scene sets its own `rectWidth` | 現在のシーンの呼び出しがその prop を渡している。行にはこのシーンの値が表示される。呼び出しが値をそのまま書いているときは、行の **×** で呼び出しから取り除ける。そうでないときは、その prop を渡していないシーンから共有の値を編集する |
| `rectWidth`'s shared value is written as an expression | `{ rectWidth = W * 2 }` のように、デフォルト値が計算されている |
| `PriceTag` doesn't take its props as `{ … }` | コンポーネントが `props.rectWidth` を読んでいて、書き込むデフォルト値の場所がない |
| Can't find where `rectWidth`'s shared value is written | コンポーネントの中に引数が見つからない |
| This file is outside the project | コンポーネントのファイルが、エントリファイルのフォルダの外か `node_modules` の中にある |

選んでいた選択肢を選べないとき（たとえば、Price で **This scene** を選んだあと、ほかのシーンも描画している呼び出しのあるシーンでその要素を選んだとき）も、Celesta はもう一方に切り替えません。どちらのタブも浮き上がらず、タブの下の行が警告色で理由を示し、選択肢を選び直すまで、編集はその理由で断られます。

### 値を取り除く

**This scene** では、現在のシーンの呼び出しで値を渡している行に **×** があり、そのツールチップは **Use the shared value** です。クリックすると呼び出しからその属性を取り除き、シーンは共有の値を使うようになります。要素に書かれた値には **This scene** では **×** がありません。取り除くとすべてのシーンに及ぶためで、フィールドを空にしても値が戻ります。**Shared value** では、要素に書かれた値はいつもどおり取り除けます。このシーンが自分で値を指定している行にも、呼び出しが値をそのまま書いていれば **Use the shared value** の **×** があり、呼び出しからその属性を取り除きます。引数のデフォルト値には **×** がありません。**Component** セクションは選択肢の対象外で、その行はこれまでどおり呼び出しに書き込み、呼び出しから取り除きます。

### ドラッグとテキストの編集

レイヤーをドラッグしているあいだ、横のラベルには 2 行目として **Edits change this scene**（シーンがコンポーネントを 2 回以上呼び出しているときは **Edits change this `<PriceTag>` only**）または **Edits change the shared value** が表示され、ヘッダーにも要素の名前の下に同じ表示が出ます。キャンバスでのドラッグ、ラベルのドラッグ、キャンバス上でのテキストの編集は、始めたときに選ばれていた選択肢で書き込みます。その選択肢で断られる操作は始まりません。キャンバスには、書き込めない prop のハンドルが表示されず、レイヤーのサイズの prop のどれかを書き込めないときはサイズのハンドルも表示されません。ラベルのドラッグやダブルクリックは、ロックされた行と同じく、代わりに理由を表示します。離したときや確定したときにその選択肢を選べなくなっていたら、もう一方で書き込むことはせず、理由を添えて断ります。断られたテキストの編集は開いたまま残り、プレビューの左上に理由が表示されるので、選択肢を選んでもう一度 Enter を押せます。ほかのレイヤーを選ぶ、再生位置を動かす、再生を始める、**File** のコマンドを使う、のいずれかをすると、何も書き込まずに編集を終えます。

### シーンを走査しているあいだ

「編集で何が変わるかを確かめる」で説明した走査が答えを出すまでは、**Edits change** のあとにタブの代わりにその状態が表示されます。

| 表示 | 意味 |
| --- | --- |
| Scanning scenes… | 走査がまだ終わっていない |
| Couldn't scan scenes: `<error>` | 走査中に、あるフレームでコンポジションが失敗した |
| Not found in the scene scan | 走査でこの要素が見つからなかった |
| The scenes are not scanned | このコンポジションでは走査が動いていない |

そのあいだも、呼び出し側で指定された値（**Set at** の付いた行や **Component** セクションの行）は、その要素で以前に **Shared value** を選んでいないかぎり、選択肢がないときと同じく呼び出しに書き込みます。それ以外の値を行で確定すると、走査が動いているあいだは行の下に **Scanning scenes…** と表示して待ち、走査が終わったところで書き込みます。その要素で以前に選択肢を選んでいれば、その選択肢で書き込みます。そうでなければ、確定したときに選択肢は見えていなかったので、走査が終わった時点で有効な選択肢が **This scene** のときだけ書き込みます。その時点で **This scene** を選べなくなっていたら、共有の値には書き込まず、**The scenes were scanned while editing; edit again** として断ります。ほかのレイヤーを選んだときやインタラクティブモードをオフにしたときは、走査を待ちません。待っていた値は書き込まず、次にクリックするまでプレビューの左上に **Not saved: the scenes were still being scanned** と表示します。走査が動いていないとき（走査が失敗した、要素が見つからなかった、シーンを走査していない）は、そうした値を **Edits change** のあとの表示を理由に断ります。

キャンバスでのドラッグ、ラベルのドラッグ、テキストの編集は、走査を待ちません。そうした値を書き込む操作は、**Edits change** のあとにタブ以外が表示されているあいだは始まらず、その表示を理由として示します。すでに始まっていた操作は、離したときや確定したときに、その表示を理由に断ります。走査中に始めた、呼び出し側で指定された値を書き込む操作が、走査が要素を共有されていると判断したあとで終わったときは、始めたときに選択肢が見えていなかったので、**The scenes were scanned while editing; edit again** として断ります。

## タイムラインでタイミングを変える

インタラクティブモードでは、選択した要素が描かれる範囲やシーンの長さをタイムラインで変えられ、Celesta が結果をソースに書き込みます。ドラッグしているあいだは何も書き込みません。帯やチャプターと、つかんだ端の横のラベルがポインタに付いて動き、プレビューは再生ヘッドの位置のフレームを表示し続けます。値を書き込むのは、マウスを離したときの 1 回だけです。押してから 3 ピクセル未満しか動かさなかったときはクリックとみなし、帯やチャプターをクリックしたときと同じく移動します。離す前に Escape を押すと、何も書き込まずにすべて元に戻ります。再生を始めたときも、何も書き込まずにドラッグを終えます。値は整数のフレームで、ドラッグはタイムラインの表示範囲の外まで続けられます。

ドラッグしているあいだ、つかんだ端は 6 ピクセル以内に近づくと、再生ヘッド、チャプターの端、動かないほかの帯の端に吸着します。Shift を押しているあいだは吸着しません。ドラッグを始めた位置に吸着することはありません。

### 要素の帯をドラッグする

選択した要素が自分の `<Sequence>` か `<Series.Sequence>` の中にあるときは、再生ヘッドの位置の塗りつぶしの帯の上、そのウィンドウの両端にグリップが付きます。対象になるのは要素を囲むいちばん内側のもので、`@celesta/react` からインポートしていれば、`Seq` や `C.Sequence` のような別の名前でもかまいません。端の上ではポインタがリサイズの矢印になります。端をドラッグするとその端が動き、中ほどをドラッグするとウィンドウ全体が動きます。

| グリップ | `<Sequence>` で書き込むもの | `<Series.Sequence>` で書き込むもの |
| --- | --- | --- |
| 始まりの端 | `from` と `durationInFrames`（終わりは動かない） | `offset` と `durationInFrames` |
| 終わりの端 | `durationInFrames` | `durationInFrames` |
| 中ほど | `from` | `offset` |

- 値は、ウィンドウを置いたタイムライン（シーンなど）のフレームです。`from={30}` を右に 15 フレームドラッグすると `from={45}` になります。
- 書いていない prop は、帯が示す値から始まり（`from` と `offset` は 0、`durationInFrames` はウィンドウの長さ）、ドラッグで追加されます。`durationInFrames` のない `<Sequence>` の中ほどをドラッグしたときも、表示されている長さで `durationInFrames` を追加します。これがないと、ウィンドウは親の終わりで終わり続けるためです。
- ウィンドウは 1 フレーム以上の長さを保ち、`<Series.Sequence>` は `<Series>` より前には始まりません。
- `<Series.Sequence>` の終わりの端や中ほどをドラッグすると、同じ `<Series>` のそれより後の項目も、`<Series>` が並べるとおりに動きます。始まりの端をドラッグしたときは、後の項目は動きません。
- そのウィンドウを通して描かれる要素の帯は、すべてドラッグに付いて動きます。終わりの端か中ほどをドラッグしたときは、`<Series>` の後の項目を通して描かれる帯も動きます。

ラベルは変わる値を示します（`from 30 → 45`、始まりの端なら `from 30 → 45 · durationInFrames 60 → 45`）。`durationInFrames` のない `<Sequence>` の中ほどをドラッグしたときは、追加する長さも `from 30 → 45 · durationInFrames 60` のように示します。フレームの範囲が、置かれたシーンやそのパートとちょうど同じ `<Sequence>` は、シーンのものとみなします。グリップは付かず、要素は自分のタイミングを持たないものとして扱われます（後述の「要素に自分のタイミングを付ける」を参照）。

値は「キャンバス上でレイヤーを動かす」の規則で書き込みます。数値は置き換え、書いていない prop は追加し、1 か所でだけ使う `const` は宣言の場所で置き換え、`<Sequence from={start}>` の `start` のような自作のコンポーネントの prop は、コンポーネントを呼び出す場所に書き込みます。ウィンドウが共有されているかどうかは、選択した要素ではなく、ウィンドウで決まります。ウィンドウが自作のコンポーネントの中に書かれていて、そのコンポーネントの 2 つ以上の呼び出しがウィンドウを描くとき、共有されています。たとえば、2 つのシーンが描くコンポーネントや、子を `<Sequence>` で包む `Delayed` コンポーネントを、それぞれのシーンが自分の要素を囲んで呼び出す場合です。1 つのシーンで、ほかのシーンも描くコンポーネントを囲む `<Sequence>` のように、1 回だけ描かれるウィンドウは、要素にどの選択肢が表示されていても、書かれている場所に書き込みます。`defineScenes` のエントリが描くコンポーネントに直接書かれたウィンドウは、そのコンポーネントをほかの場所でも呼び出していても、そのシーン自身のものとして書かれている場所に書き込み、ドラッグは描かれているすべての場所を変えます。共有されたウィンドウは、「1 つのシーンだけを変えるか、すべてのシーンを変えるか」で説明したとおり、プロパティのセクションの上で選んだ選択肢に従います。共有されているのがウィンドウだけで、選択した要素に選択肢が表示されないときは、**This scene** に従います。**This scene** では、ドラッグが書き込む値（中ほどなら `from`）を `sequenceFrom` のようなコンポーネントの新しい prop に移し、新しい値をこのシーンの呼び出しで渡します。**Shared value** では、自分の値を指定していないすべてのシーンが変わります。シーンがそのコンポーネントを 2 回以上呼び出しているとき、**This scene** は選択した要素を描く呼び出しでだけ新しい値を渡し、シーンのほかの呼び出しは古い値を新しい prop のデフォルトとして保ちます。共有されたウィンドウをドラッグしているあいだ、ラベルには 2 行目として **Edits change this scene** または **Edits change the shared value** が表示されます。キャンバスでのドラッグと同じく、その選択肢で断られるグリップはドラッグできず、理由を表示します。たとえば、シーンを走査しているあいだは **Scanning scenes…**、**Shared value** でこのシーンの呼び出しがその prop を自分で渡しているときは **This scene sets its own `sequenceFrom`** です。ドラッグは押したときに選ばれていた選択肢で書き込み、離したときにその選択肢で書き込めなくなっていたら、何も書き込みません。

ドラッグできないグリップの上では、ポインタが禁止の形になり、ポインタを合わせると理由が表示されます。グリップは、書き込む prop のロックの理由（「キャンバス上でレイヤーを動かす」の表を参照）でロックされます。たとえば `from={cut - 9}` では、始まりの端と中ほどが **Written as an expression: cut - 9** でロックされ、終わりの端はドラッグできます。次のような理由では、すべてのグリップがロックされます。

| 理由 | 意味 |
| --- | --- |
| Timing inside a loop or freeze frame can't be dragged | 要素にいちばん近いウィンドウが `<Loop>` か `<FreezeFrame>` の中にある |
| Not a `<Sequence>` or `<Series.Sequence>` of @celesta/react | ウィンドウがほかのラッパーのもの、またはファイルが `@celesta/react` からインポートしていない `Sequence` のもの |
| Couldn't find this element in the source | プレビューが見つけた場所に、ファイルのウィンドウがもうない（保存後の再読み込みの途中など） |
| The source is still being read | 要素を選択した直後などで、Celesta が要素のソースを読んでいる |
| Select the layer again | Celesta 自身が書き込んだ直後などで、レイヤーについて読んだ内容が古くなっている |
| This file is outside the project | ウィンドウが、エントリファイルのフォルダの外か `node_modules` の中のファイルに書かれている |
| Not saved: the code failed to reload | Celesta が書き込んだあと、コンポジションの再読み込みに失敗した |
| Not saved: the preview stopped unexpectedly | プレビューが止まった。Celesta を起動し直す |

ドラッグを離して何も書き込まなかったときは、次にクリックするまで、グリップの横に **Not written:** で始まる理由が表示されます。ドラッグに使った選択肢で書き込めなくなったとき（**Not written: The scenes were scanned while editing; edit again** など）、ドラッグ中にソースが再読み込みされたとき、書き込みに失敗したとき（**Not written: The source changed while editing** など）です。

### シーンの終わりをドラッグする

**Chapters** の行では、Celesta が書き込める `defineScenes` のエントリから来たチャプターの終わりをドラッグできます。ドラッグするとそのエントリの `durationInFrames` が変わり、同じリストでそれより後のシーンが、`defineScenes` が並べるとおりに動きます。ドラッグできる終わりの上では、ポインタがリサイズの矢印になり、終わりが強調されます。ラベルには `durationInFrames 90 → 100` のように変化が表示されます。

```ts
const SCENES = defineScenes([
  { id: 'intro', durationInFrames: 90, Scene: Intro },
  { id: 'main', durationInFrames: 120, Scene: Main },
]);
```

Celesta は再読み込みのたびに、エントリファイルのフォルダとその下にある `.ts` と `.tsx` のファイルを読み（`node_modules`、`dist`、`.tmp`、`.git` は除きます）、`@celesta/react` からインポートした `defineScenes([...])`（別名でのインポートや、`import * as C` での `C.defineScenes` も含みます）の呼び出しのうち、リストを書き下したものを探します。書き下したリストとは、`id` が文字列の `{ … }` のエントリを並べた配列です。`...CHAPTERS.map(…)` のようにほかのものを含むリストは対象外です。チャプターの id を持つエントリは 1 つだけでなければならず、そのエントリの `durationInFrames` は、数値か、同じファイルの `const` でなければなりません。`const` は、ほかのどこからも読まれず、ファイルがエクスポートしていないものに限ります。

エントリファイルがコンポジションの長さをリストの長さとして書いているとき、つまり `<Composition durationInFrames={SCENES.durationInFrames}>` の `SCENES` が、同じファイルにあるリストの `const` か、拡張子を付けないパスから名前を指定してインポートしたもの（別名でもかまいません）のときは、コンポジションの長さもドラッグに付いて変わります。たとえば `import { SCENES } from './timeline'` は、`timeline.ts`、`timeline.tsx`、`timeline` フォルダの `index.ts` を指します。このときシーンを長くすると、コンポジションも長くなります。それ以外のとき（`durationInFrames={300}` など）は、コンポジションの長さは変わりません。ドラッグしたシーンより後のシーンがコンポジションの終わり以降に始まる手前、またドラッグした終わりがコンポジションの終わりを越える手前で、ドラッグは止まり、終わりの横に **The composition is 300 frames long** と表示されます。

- シーンは 0 フレームまで縮められます。0 フレームのシーンはリストに残りますが、再生されません。後のシーンが、リストの最初のシーンより前に始まることはありません。
- コンポジションの終わりで切れているチャプターは、見えている長さにドラッグの分を足した長さで書き込みます。エントリの長さちょうどに戻したときは、何も書き込みません。
- 動くのは、同じリストでドラッグしたシーンより後のシーンだけです。ほかのリストのチャプターや、`listChapters()` などで自分で並べたチャプターは動きません。
- 終わりは、再生ヘッドと、動かないチャプターの端に吸着します。
- シーンのリストはコンポーネントの prop ではないので、**Edits change** の選択肢は関係しません。

ドラッグできない終わりの上では、ポインタが禁止の形になり、ポインタを合わせると理由が表示されます。

| 理由 | 意味 |
| --- | --- |
| Reading source… | Celesta が、今回の再読み込みに合わせてファイルを読んでいる |
| Can't find scene `<id>` in the source | 書き下したリストに、この id のエントリがない、または 2 つ以上ある。スプレッドを含むリストのシーンも、これにあたる |
| Not a `defineScenes` entry | チャプターが `listChapters()` で並べたパートのようにほかのチャプターの中にあり、その id のエントリを持つリストがない |
| Written as an expression: `<expression>` | `S.field - S.words` のように、長さが計算されている。ツールチップの続く行には、式が読む名前が 1 つずつ、`BAR = 30` のような値か、たどれない理由とともに並ぶ |
| Exported, so other files may read it | 長さが、ファイルがエクスポートしている `const` で、変えるとほかのファイルも変わりうる |
| `<name>` is used in `<count>` places | その `const` をほかの場所でも読んでいる |
| Scene `<id>` has no durationInFrames | エントリに長さが書かれていない |

離したときにエントリが変わっていたりロックされていたりしたとき、または書き込みに失敗したときは、何も書き込まず、次にクリックするまで、**Not written: The source changed while editing** のようにラベルが理由を示します。

### 要素に自分のタイミングを付ける

シーン全体に描く背景のように、自分のウィンドウを持たない要素にはグリップが付きません。代わりに、再生ヘッドの位置の塗りつぶしの帯の始まりに **Set timing** ボタンが表示されます。クリックすると再生を止め、再生ヘッドからシーンの終わりまでの `<Sequence>` で要素を囲みます。

```tsx
// 変更前: 再生ヘッドは 120 フレームのシーンの 45 フレーム目
<Rect width={1280} height={720} fill="#14161C" />

// 変更後
<Sequence from={45} durationInFrames={75}>
  <Rect width={1280} height={720} fill="#14161C" />
</Sequence>
```

- `from` は、要素が描かれるシーンの始まりから数えます。`<Scenes>` や `<Sequence>` の外で、コンポジション自身のタイムラインに置いた要素では、再生ヘッドのフレームが `from` になり、長さは再生ヘッドの位置のシーンの終わりまで、どのチャプターにも入っていなければコンポジションの終わりまでです。
- `<Sequence>` は要素と同じ深さに、要素は 1 段深くインデントします。ファイルが使っているタブかスペースに合わせ、ほかの部分の書式は変えません。`<Group><Rect /></Group>` のようにほかのコードと同じ行にある要素は、その行の中で囲みます。
- `Sequence` は、ファイルの `@celesta/react` からのインポートに追加します。名前がソートされていれば、その順の位置に入れます。そのインポートがなければ、最後のインポートの次の行に新しいインポートを書きます。ファイルが別の名前でインポートしているときは、`<Seq>` や `<C.Sequence>` のようにその名前を使います。
- これで 1 回の変更です。1 回元に戻すと、`<Sequence>` とインポートの両方が戻ります。

ボタンのツールチップには **Animations inside start at the new start** と表示されます。`<Sequence>` の中では `useCurrentFrame()` が `<Sequence>` の始まりから数えるので、新しい `<Sequence>` の中にあって自分でフレームを読むコンポーネント（`interpolate(frame, [0, 20], [0, 1])` でフェードインするタイトルなど）は、シーンの始まりではなく再生ヘッドの位置からアニメーションを再生するようになります。これは `<Sequence>` の意味そのものなので、Celesta はそのままにします。新しい `<Sequence>` の外で計算した値（シーンのコンポーネントが自分の `frame` から計算する `opacity` など）のタイミングは変わらず、要素が描かれるフレームが少なくなるだけです。

複数のシーンが描く自作のコンポーネントの中に書かれた要素では、**Set timing** はコンポーネントに書き込むので、すべてのシーンが変わります。そのため、プロパティのセクションの上で選んだ選択肢に従い、**Shared value** のときに使えます。このとき `from` は、それぞれのシーンの始まりから数えます。`durationInFrames` は、今のシーンの再生ヘッドから後に残っている長さで、すべてのシーンに同じ値が書き込まれるので、それより長いシーンでは要素がシーンより先に終わります。書き込めないときは、ボタンが理由を添えて無効になります。

| 理由 | 意味 |
| --- | --- |
| Wrap the element in a parent first | 要素がほかの要素の子ではない。コンポーネントが返すものの根元、prop の値、または `{show && <Rect />}` や `.map()` のような `{…}` の中に書かれている |
| `Sequence` here is not Celesta's | ファイルが `Sequence` という名前をほかのものに使っている（自分の宣言、型だけのインポート、ほかのモジュールからのインポート） |
| No frame left after the playhead | 再生ヘッドがシーンの終わりにある |
| Can't be set per scene yet | 要素が共有されていて、**This scene** が選ばれている。すべてのシーンにタイミングを付けるには **Shared value** を選ぶ |
| Scanning scenes… | 要素が共有されているかどうかが、走査でまだわからない。わからなかったときは「シーンを走査しているあいだ」のほかの表示になる |
| This file is outside the project | 要素のファイルが、エントリファイルのフォルダの外か `node_modules` の中にある |

要素を選択した直後や再生ヘッドを動かした直後など、Celesta が要素のソースを読んでいるあいだは、ボタンは表示されません。ファイルがそのあいだに変わっていたときなど、書き込みに失敗したときは、次にクリックするまで、帯の横に **Not written:** で始まる理由が表示されます。

## キャンバスに要素を追加する

インタラクティブモードでは、ツールの行の先頭にある **Add** メニューから、**Rect**、**Ellipse**、**Circle**、**Text**、**Image**、**Video** をソースに追加できます。項目を選び、キャンバスの上に描きます。新しい要素は親になる `<Group>` の最後の子として書き込まれるので、そのグループのほかの子より手前に描かれます。

### 追加する先

メニューの 1 行目には、**Add to `<Group>` in `<PriceTag>`** のように親が表示されます。`PriceTag` はそのグループが書かれているコンポーネントで、コンポーネントの外なら **Add to `<Group>`** とだけ表示されます。選択しているレイヤーが `<Group>` ならそれが親になり、そうでなければ、**Source chain** に並ぶ、そのレイヤーを囲むいちばん近い `<Group>` が親になります。別のグループに追加するには、そのグループを選択します。たとえば、その行の **Select** ボタンで選択できます。親になれるのは、Celesta の `<Group>`（どの名前で import していてもかまいません）で、プロジェクトの中のファイルに書かれ、子要素がタグのあいだに書かれているグループです。子が `{children}` や `{props.children}` のような prop だけのグループは、呼び出し側が渡したものを表示しているので、その外側でいちばん近いグループが代わりに親になります。子が `{items.map(…)}` なら親になれて、新しい要素はその後ろに入ります。中身のない `<Group />` はクリックできるものを描かないので、今のところ親にはできません。

グループが共有されているとき、つまりコードの複数の場所から、または複数のシーンで描かれるコンポーネントの中に書かれているときは、選択した要素の **Edits change** の選択（前述の「1 つのシーンだけを変えるか、すべてのシーンを変えるか」を参照）で決まります。**Shared value** なら、そのグループに追加するので、そのコンポーネントが描かれるすべての場所に要素が現れます。**This scene** のとき、および選択した要素にその切り替えがないときは、共有されたグループを飛ばし、その外側で、シーン自身のコードに書かれたいちばん近いグループに追加します。このとき 1 行目の末尾に **· This scene** が付きます。

### 描く

項目を選ぶと再生は一時停止します。ボタンには **Adding Rect** のように選んだ項目が表示され、その横の行には、追加する先の親と操作のしかたが **to `<Group>` in `<PriceTag>` · Drag a box, or click · Esc cancels** のように表示されます。キャンバスの上ではポインタが十字になり、ドラッグ中は書き込まれる形がアクセントカラーの枠で表示されます。

| 項目 | 描き方 | ドラッグせずにクリックしたとき |
| --- | --- | --- |
| **Rect**、**Ellipse** | 矩形をドラッグする | クリックした位置を左上の角とする 200 × 200 の矩形 |
| **Circle** | 中心から外側へドラッグする | クリックした位置を中心とする半径 100 の円 |
| **Text** | テキストを始める位置をクリックする | — |
| **Image**、**Video** | ファイルを選んでから矩形をドラッグする。ドラッグで幅が決まり、高さはファイルの縦横比に従う | クリックした位置を左上の角とする幅 400 |

画面上で 4 ピクセル未満しか動かさなかった押下はクリックとして扱います。サイズは親の単位で書き込むので、要素は描いたとおりの位置に現れます。たとえば、2 倍に拡大したグループの中で幅 200 ピクセルの矩形をドラッグすると `width={100}` と書き込まれ、回転したグループの中では要素もグループと一緒に回転します。どの辺も 1 より小さくはなりません。SVG のように Celesta がファイルの縦横比を読めないときは、枠はドラッグに従いますが、書き込むのは幅だけなので、絵は自身の縦横比を保ちます。

**Image** と **Video** は、先にファイルを選ぶダイアログを開きます。パスはエントリファイルのフォルダからの相対パスで書き込み、そのフォルダの外にあるファイルは、**Source** の行の **Choose…** と同じく、先にフォルダの中の `assets` フォルダにコピーします。ファイルを選ばずにダイアログを閉じると、追加は終わります。

ドラッグはフレームの中から始めます。終わりはフレームの外でもかまいません。Escape を押すと、何も書き込まずに取り消します。1 回のドラッグかクリックで追加する要素は 1 つです。もう 1 つ追加するときは、項目をもう一度選びます。選択が変わったとき、**Select layers** をオフにしたとき、再生を始めたとき、コンポジションを再読み込みしたときも、追加は終わります。

要素は、項目を選んだときに表示されていた親に追加します。マウスを離す前に親が変わると、何も書き込みません。書き込まなかった理由は、次にクリックするまでプレビューの左上に表示されます。

| 表示 | 意味 |
| --- | --- |
| The parent changed; choose the item again | 親が、項目を選んだときに表示されていたものではなくなった |
| The source changed while editing | Celesta の外での編集などで、グループが書かれていた位置からなくなった |
| The source is still being read | 親の位置や、キャンバス上での親の座標系をまだ読んでいる |
| Couldn't show the file dialog: `<error>` | ファイルを選ぶダイアログを開けなかった |
| Couldn't use the chosen file: `<error>` | 選んだファイルを `assets` フォルダにコピーできなかった |

次の節の表の理由も、描いているあいだに生じたときはここに表示されます。

### 書き込まれる内容

要素はリテラルの値だけで書き込まれます（数値は小数第 2 位までに丸めます）。そのため、どの値もあとからほかの値と同じように編集できます。

| 項目 | 書き込む prop |
| --- | --- |
| **Rect**、**Ellipse** | `x` と `y`（矩形の左上の角）、`width`、`height`、`fill="#4F7CFF"` |
| **Circle** | 中心を表す `x` と `y`、`anchorX={0.5}`、`anchorY={0.5}`、`radius`、`fill="#4F7CFF"` |
| **Text** | `x`、`y`、`fontSize={48}`、`color="#4F7CFF"`、テキストの `Text` |
| **Image**、**Video** | `src`、`x`、`y`、`width` |

要素は再生ヘッドの位置から始まり、親を囲むいちばん近いタイミングの範囲の終わりまで表示されます。範囲は、グループを囲む `<Sequence>` や `<Scenes>` のシーンです。コンポジション自身のタイムラインにあるグループなら、再生ヘッドの位置のシーン（シーンの外ならコンポジションの終わりまで）です。要素は `<Sequence>` で囲まれ、その `from` はその範囲の始まりから数えます。選択した要素そのものを囲む、グループの内側の `<Sequence>` は、新しい要素を囲まないので数えません。グループを囲む 120 フレームの `<Sequence>` の 45 フレーム目で `<Rect>` を追加すると、次のように書き込まれます。

```tsx
<Sequence from={45} durationInFrames={75}>
  <Rect x={120} y={80} width={320} height={180} fill="#4F7CFF" />
</Sequence>
```

`<Sequence>` がなくても同じ範囲に表示されるとき、つまりグループを囲む `<Sequence>` やシーンの最初のフレームで追加したときと、フレーム 0 からコンポジションの終わりまで表示されるときは、`<Sequence>` を書き込みません。範囲の残りが 1 フレームに満たないときは、範囲の最初のフレームであっても、1 フレームの `<Sequence>` で囲みます。

追加する行は、グループの開始タグより 1 段深く、ファイルで使われているタブかスペースでインデントします。`Rect`、`Text`、`Image`、`Video`、`Sequence` は `@celesta/react` から、`Ellipse` と `Circle` は `@celesta/shapes` から import します。ファイルがまだ import していない名前は、そのパッケージからの `import { … }` に書き足します（並べ替えてあるリストは並びを保ちます）。そうした import がなければ、最後の import の後ろに、その import と同じ引用符とセミコロンの書き方で新しい import の行を加えます。import が 1 つもないファイルでは、先頭に `import { Rect } from "@celesta/react";` を加えます。別名で import している名前はその別名で書き、`import * as C from "@celesta/react"` のときは `<C.Rect>` と書きます。

1 回の追加は 1 回の変更で、1 回元に戻すと、要素とその import がまとめて取り除かれます。再読み込みのあと、プレビューが新しい要素を描いたところでその要素が選択されます。再読み込み後のフレームに要素が描かれなければ、元の選択がそのまま残ります。選択したレイヤーが別の場所に書かれた要素だったときは、選択を解除します。

### 項目が使えないとき

親の名前の下の行には、すべての項目が使えない理由が表示され、項目ごとの理由は項目の下に並びます。

| 理由 | 意味 |
| --- | --- |
| Select a group, or a layer inside one, to add into | 何も選択していないか、選択したレイヤーを囲むグループに親になれるものがない |
| No group in this scene's own code to add into | **This scene** で、親になれるグループがすべて共有されている |
| The source is still being read | 再読み込みの直後などで、選択したレイヤーのソースをまだ探しているか読んでいる |
| Scanning scenes…、Couldn't scan scenes: `<error>`、Not found in the scene scan、The scenes are not scanned | グループが共有されているかどうかがまだわからない。「編集で何が変わるかを確かめる」を参照 |
| 「選択肢を選べないとき」に挙げた理由 | 選択した要素で使われる **Edits change** の選択肢を選べない。以前に選んだ選択肢を選べないときと、何も選んでおらず両方とも選べないときがある。タブのツールチップにも同じ理由が表示される |
| Can't add inside a loop or freeze frame | グループを囲むいちばん近い範囲が `<Loop>` か `<FreezeFrame>` |
| Can't draw into a group turned in 3D | グループかその外側のグループに `rotationX`、`rotationY`、`perspective` がある |
| Can't draw into a group scaled to zero | グループかその外側のグループの拡大率が 0 で、その中では描いたものに大きさがない |
| `Ellipse` comes from `@celesta/shapes`, which this composition doesn't import | **Ellipse** と **Circle** だけ。先にコンポジションで `@celesta/shapes` を import する |
| `Rect` here is not Celesta's | ファイルが別の `Rect` を宣言しているか import していて、その項目だけが使えない。別の `Sequence` があるとき（**`Sequence` here is not Celesta's**）は、要素を `<Sequence>` で囲む必要があれば、すべての項目が使えない |

## 元に戻す

元に戻す（`⌘ Z`、`Ctrl Z`）とやり直し（`⌘ Shift Z`、`Ctrl Shift Z`）で、Celesta が書き込んだ変更を順にたどれます。キャンバス、プロパティの行、props ファイルの **Properties** セクションのどれからの変更も、同じ履歴に最大 100 件まで残り、別のファイルを開くと消えます。確定した 1 つの行、スイッチ、メニューの選択、ピッカーで選んだ色、選んだファイル、ラベルのドラッグ、取り除いた prop、キャンバス上で編集したテキスト、帯やシーンの終わりのドラッグ、**Set timing** が、それぞれ 1 回の変更です。コンポーネントの呼び出し側とコンポーネントのように 2 つのファイルに書き込んだ変更も、1 回で元に戻し、1 回でやり直します。変更のあとに、変更が書き込んだファイルがほかの場所で編集されていた場合、Celesta はあなたの編集を上書きしないよう元に戻すのを断り、どちらのファイルも変更しません。
