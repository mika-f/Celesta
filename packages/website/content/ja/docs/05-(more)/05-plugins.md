コンテンツプラグインは、Celesta 本体にない機能を追加します。独自のコードで描くレイヤーや、音声合成チャンネルのようなコンポーネントライブラリです。プラグインはコンピューターに置くフォルダーで、コンポジションからは `@celesta-plugin/<id>` としてコンポーネントを import します。

プラグインは新しい機能で、今後も変わる可能性があります。デスクトップアプリのプレビューと `celesta-exporter` で動作し、`@celesta/web` と CPU リファレンスレンダラーでは動作しません。

## プラグインを入れる

プラグインは `celesta-plugin.json` のあるフォルダーです。いちばん簡単なのは、ユーザーのプラグインフォルダーに置く方法です。

| OS | ユーザーのプラグインフォルダー |
| --- | --- |
| Windows | `%APPDATA%\Celesta\plugins` |
| macOS | `~/Library/Application Support/Celesta/plugins` |
| Linux など | `$XDG_DATA_HOME/celesta/plugins`（未設定なら `~/.local/share/celesta/plugins`） |

Celesta は次の順にプラグインを探し、同じ id のプラグインが複数あれば先に見つかったものを使います。

1. エクスポーターの各 `--plugin-dir`
2. 環境変数 `CELESTA_PLUGIN_PATH` の各フォルダー（Windows は `;`、それ以外は `:` 区切り）
3. デスクトップアプリでは、開いているプロジェクトのプラグインフォルダー（信頼したあと。[プロジェクトに同梱するプラグイン](#プロジェクトに同梱するプラグイン)を参照）
4. ユーザーのプラグインフォルダー
5. デスクトップアプリの [Plugins タブ](#plugins-タブ)で追加したフォルダー
6. Celesta に同梱のプラグインフォルダー（Windows は実行ファイルの隣の `plugins`、macOS のアプリは `Contents/PlugIns`、それ以外は実行ファイルのフォルダーから見た `../lib/celesta/plugins`）

1・2・3・5 で指定するフォルダーはプラグインそのものでも、複数のプラグインを入れたフォルダーでもかまいません。`CELESTA_PLUGIN_PATH` には絶対パスを指定してください。相対パスは、Celesta を起動した場所によって指すフォルダーが変わるため読み飛ばされます。

macOS や Linux などの Unix 系では、3〜6 のフォルダーや、そこにあるプラグインの中身を他のユーザーが書き換えられる場合（グループやその他に書き込み権限がある、所有者が root でも自分でもない）は使いません。プラグインのファイルを書き換えられる人は、それを使う人の権限でコードを動かせるからです。`chmod -R go-w` で書き込み権限を外してください。

```sh
celesta-exporter --react film.tsx out.mp4 --plugin-dir ~/celesta-plugins
```

## 信頼と承認

プロジェクトを開くと、そのコードがコンピューター上で動きます。プラグインも自分のコードを動かします。そのためデスクトップアプリは、どちらも動かす前に確認します。

- **プロジェクト**：初めて開くとき、そのフォルダーを信頼するかを尋ねます。信頼するまでは何も評価しません。インターネットからダウンロードしたプロジェクトは、その旨が確認に表示されます（Windows）。**File > Create New Project** で作ったプロジェクトは最初から信頼済みです。信頼が及ぶのはそのプロジェクトのフォルダーで、その下にある、自分の `celesta.config.json` を持つ別のプロジェクトには及びません。プロジェクトのルートに `celesta.config.json` があれば信頼は記憶されます。ないフォルダーでは、アプリを終了するまで有効で、次に起動したときにまた尋ねます。プロジェクトを作ると `celesta.config.json` も作られます。
- **プラグイン**：ユーザーのプラグインフォルダーや追加したフォルダーにあるプラグインと、プロジェクトが持ち込むプラグインは、許可するまで動きません。見つけたときに確認し、更新などでマニフェストやマニフェストが指すファイル（プログラム・モジュール・型定義）が変わったときにも改めて確認します。プラグインのフォルダーにあるそれ以外のファイルは確認の対象外です。許可するまで、プラグインのコードは一切動かず、Problems には承認待ちと表示されます。それを import するプロジェクトも開けますが、プラグインのコンポーネントは何も描かないので、そのレイヤーはプレビューに出ません。コンポーネント以外の関数を `prepare` などで呼ぶと、承認待ちであることを示すエラーになります。許可すると、プラグインを使ってプロジェクトを読み込み直します。`--plugin-dir` や `CELESTA_PLUGIN_PATH` で指定したプラグインと、Celesta に同梱のプラグインは確認しません。

選んだ内容は Celesta の設定フォルダーの `settings.json` に保存されます。設定フォルダーは Windows では `%APPDATA%\Celesta`、macOS では `~/Library/Application Support/Celesta`、それ以外では `$XDG_CONFIG_HOME/celesta`（未設定なら `~/.config/celesta`）です。

`celesta-exporter` と MCP サーバーは確認しません。上のフォルダーのうちプロジェクトのもの以外にあるプラグインを、アプリで許可したかどうかにかかわらず使います。

### プロジェクトに同梱するプラグイン

プロジェクトは自分のフォルダーにプラグインを入れて持ち込めます。プロジェクトのルートにある `celesta.config.json` に、そのフォルダーを書きます。

```json
{
  "plugins": {
    "paths": ["./plugins"]
  }
}
```

各パスはプロジェクトのルートからの相対パスで、ルートの中を指す必要があります。デスクトップアプリは、プロジェクトを信頼したあと、これらのフォルダーを `CELESTA_PLUGIN_PATH` の次、ユーザーのプラグインフォルダーの前に探します。`celesta.config.json` のあるフォルダーが、信頼の確認で表示されるプロジェクトのルートにもなります。このファイルがなければ、エントリーのあるフォルダーがルートです。`celesta-exporter` はこのファイルを読まないので、フォルダーを `--plugin-dir` で指定してください。

## Plugins タブ

デスクトップアプリはプロジェクトを開くたびにプラグインを探します。右側のドックの **Plugins** タブには、見つかったすべてのプラグイン（同じ id が複数あれば、使われる 1 つ）が一覧表示されます。各プラグインについて、次の内容がわかります。

- どこから見つかったか（プロジェクト、ユーザーのプラグインフォルダー、追加したフォルダー、`CELESTA_PLUGIN_PATH`、Celesta に同梱のフォルダー）
- バージョン、コンポーネントだけかプログラムも持つか、そのプログラムがこのコンピューター向けに作られているか
- オン・オフ・承認待ちのどれか

このタブでは次の操作ができます。

- 承認待ちのプラグインを許可する
- プラグインをオフにしたり、オンに戻したりする（オフのプラグインは、アプリでも `celesta-exporter` でも動きません）
- プラグインのフォルダーを開く
- ユーザーのプラグインフォルダーを開く（なければ作ります）
- プラグインを入れたフォルダーを追加する（ユーザーのプラグインフォルダーの次に探されます）、追加したフォルダーを外す
- **Reload Plugins** で読み込み直す（**File** メニューにもあります）。アプリを開いたまま入れたプラグインも、これで読み込めます。

変更した内容はほかの選択と同じく `settings.json` に保存され、プロジェクトは新しい設定のプラグインで開き直されます。読み飛ばしたプラグインとその理由は、タブの下と Problems タブに表示されます。

レイヤーを描くプラグインは独立したプログラムとして動き、フレームに必要になった時点で Celesta が起動します。プログラムはプラグインに同梱され、対応するプラットフォームごとに用意されます。

## コンポーネントを使う

```tsx
import { Composition } from '@celesta/react';
import { Flag } from '@celesta-plugin/flag';

export default function Root() {
  return (
    <Composition width={1280} height={720} fps={30} durationInFrames={150}>
      <Flag src="./portrait.png" x={80} y={160} amplitude={0.1} />
    </Composition>
  );
}
```

どのフォルダーにもないプラグインを import したエントリーは読み込みに失敗し、プラグイン名がエラーに表示されます。フレームは時刻だけで決まります。プラグインのレイヤーも props とフレームだけで決まるため、プレビュー・書き出し・シークの結果が一致します。

プラグインは、モデルの利用条件のように、レイヤーが描くものについてのお知らせを出すことがあります。デスクトップアプリはそれを Problems タブに表示し、`celesta-exporter` は一度だけ出力します。警告は `warning:`、情報だけのものは `note:` で始まります。

プロジェクトの TypeScript サポートは、各プラグインの型定義を `.celesta/plugins/` にコピーするので、コードエディターで props を補完できます。デスクトップアプリがプロジェクトを開いたときは、プロジェクト自身のプラグインと承認待ちのプラグインの型定義もコピーします。型定義はコードを実行しません。

デスクトップアプリでは、プラグインのコンポーネントを **Add** メニューから追加することもできます。メニューでは Celesta 本体の要素の後に並びます。選ぶと Image や Rect と同じように追加できます。ファイルを受け取るコンポーネントは先にファイルを尋ね、そのあとドラッグで置く場所を決めます。VRM アバターのようにモデルファイルを受け取るコンポーネントは、指定された種類のファイルだけを受け付け（`Choose a .vrm file`）、レイヤーの縦横比で枠を描きます。アプリは要素を書き込むとき、`import { Flag } from '@celesta-plugin/flag'` のようなプラグインの import も追加します。

## VRM プラグイン

リポジトリの `plugins/vrm` は、VRM 1.0 のアバター（`.vrm`）を 3D で描くプラグインです。UniVRM と同じ MToon のトゥーン調の陰影で描き、表情・まばたき・口パク・目線に加えて、モーション（`.vrma`）を再生し、髪や服を揺らせます。ビルドしてから、書き出されたフォルダーをインストールします。

```sh
pnpm install && pnpm run build:runtime   # 最初に一度、リポジトリのルートで
node plugins/vrm/build.mjs               # plugins/vrm/dist/vrm に書き出します
```

`plugins/vrm/dist/vrm` をユーザーのプラグインフォルダーにコピーするか、書き出しのときに `--plugin-dir` で `plugins/vrm/dist` を指定します。ビルドには、Celesta 本体のビルドと同じく Rust と Node.js が必要です。

```tsx
import { Composition } from '@celesta/react';
import { Vrm } from '@celesta-plugin/vrm';

export default function Root() {
  return (
    <Composition width={1920} height={1080} fps={30} durationInFrames={180}>
      <Vrm src="./avatar.vrm" camera="bust" lookAt="camera" expressions={{ happy: 0.4 }} mouth="a" />
    </Composition>
  );
}
```

| props | 内容 |
| --- | --- |
| `src` | `.vrm` ファイル（VRM 1.0）。 |
| `width`・`height`・`aspect` | レイヤーのピクセル数です。両方を指定するか、片方と `aspect`（幅÷高さ、既定は 16:9）を指定すると、もう片方が決まります。`aspect` だけなら幅は 1920 のまま、どれもなければ 1920×1080 です。指定した辺も計算した辺も 1〜16384 ピクセルでなければならず、外れると `<Vrm>` がエラーを投げます。アバターはこの解像度で描かれ、小さなレイヤーを拡大することはありません。 |
| `expressions` | 表情の重み（0〜1）。VRM のプリセット名（`happy`・`angry`・`sad`・`relaxed`・`surprised`・`aa`・`blink` など）か、モデル独自のカスタム表情の名前で指定します。`blink` や口の形より優先されます。 |
| `mouth` | 口の形（`'a'`・`'i'`・`'u'`・`'e'`・`'o'`・`'closed'`）か、`{ aa: 0.5, oh: 0.3 }` のような母音ごとの重み。5 つの母音（`aa`・`ih`・`ou`・`ee`・`oh`）をすべて設定し、指定しなかった母音は 0 になるので、モーションの口の動きは出ません。 |
| `lipSync`・`mouthSmoothing` | 口パクのトラック（`loadLipSync()` の結果や、読み上げたセリフの `lipSync`）。`mouth` がないときに使い、口の形を `mouthSmoothing` フレームかけてなめらかに切り替えます（既定は 2、0 で即座に切り替え）。`mouth` と同じく 5 つの母音をすべて設定するので、声のないところでは口が閉じます。 |
| `blink` | まばたきのタイミング。キャラクターの立ち絵と同じくシードで決まります。`false` でまばたきしません。 |
| `lookAt` | 目線の先です。`'camera'`、アバターの空間の点 `[x, y, z]`、または度数の `{ yaw, pitch }`（yaw はアバターから見て右が正、pitch は上が正）。なければ正面を向きます。 |
| `camera` | `'full'`（既定。全身）、`'bust'`（腰から上。ヒューマノイドの spine ボーンから）、`'face'`、またはアバターの空間での `{ position, target, fov?, near?, far? }`（`fov` は度数、既定は 30）。 |
| `lights` | `{ directional: [{ direction, color, intensity }], ambient }`。平行光源は 4 つまで（5 つ目でエラー）、色は `#rgb` か `#rrggbb` です。基準ライトを置き換えるので、`ambient` がなければ環境光は黒になります。`lights` がなければプラグインの基準ライト（Unity の既定の平行光源を前上方から当て、既定の環境光の色を加えたもの）を使います。光源の `intensity` と、色に `intensity` を掛けた値は、32 ビット浮動小数点数で有限に収まらなければならず、外れるとそのフレームは `lights.directional[i].intensity` を示すエラーになります。 |
| `motions` | タイムラインに置く VRM アニメーション（`.vrma`）。`[{ src, from?, loop?, fadeIn? }]` の形で、`from` はモーションが始まる、囲んでいるシーケンスのフレーム（既定は 0）、`fadeIn` は前のモーションから切り替えるのにかけるフレーム数（既定は 0）です。`from` が有限でない場合と、`fadeIn` が負か有限でない場合はエラーになります。 |
| `tracks` | モーションの上から、ヒューマノイドのボーンをキーフレームで回します。`{ head: { yaw: [{ frame, value, easing? }, …] }, … }` の形で、`pitch`・`yaw`・`roll` は度数、`x`・`y`・`z` は `hips` だけに指定でき、単位はメートルです。 |

アバターの空間はファイルのままで、単位はメートル、+Y が上、アバターは +Z を向き、左手側が +X、足元はおおむね 0 です。カメラのプリセットは、レイヤーの縦横比に合わせて、基本姿勢で立つアバターを収めます。`full` は横幅も収めるので、片側に大きく張り出した持ち物があると、アバターが中央からずれます。

モデルを開くと、プラグインはモデルの利用条件をお知らせとして 1 行ずつ出します。作者・ライセンス・各条件です。作ろうとしている動画を禁じていそうな条件は `warning` になります。アバターを使えるのが作者本人か作者が個別に許諾した人だけの場合、商用利用ができない場合、クレジット表記が必要な場合（動画を公開する場所で誰をクレジットするかも書かれます）です。ファイルに書かれていない条件は VRM 1.0 の既定値として扱われ、既定値はいちばん厳しい側です。どの場合もプラグインはアバターを描きます。使ってよいかどうかを判断するのは利用者です。

ファイルが一人称視点専用とするメッシュ（装着者自身の視点用の、頭のない体など）は、UniVRM の三人称カメラと同じく描きません。ファイルが一つのノードを二度以上指定しているときは、UniVRM と同じく最初の指定が有効になり、それ以降の指定はそれぞれ警告になります。

ほかの警告は、ファイルのうちプラグインが書かれたとおりには使わない部分を知らせます。描かないプリミティブ、マテリアルが使わずに描くテクスチャ、無視するモーフターゲットのバインドです。これらの種類と一人称視点の重複指定は、それぞれ 20 件まで並べ、残りは 1 行で件数を示します（`and 12 more primitives that are not drawn`）。

マテリアルの発光は、`KHR_materials_emissive_strength` があればその値で、なければ `VRMC_materials_hdr_emissiveMultiplier` の値で明るくなります。UniVRM と同じ読み方です。この倍率が有限の数でなければ、そのフィールド名を示してモデルを開くのを断ります。

ファイルが素の glTF PBR で指定しているマテリアル（金属やガラスの部品によくあります）は、今のところベースカラーだけの平らな色で描かれ、その名前がお知らせで示されます。VRM 0.x のファイルにはまだ対応していません。変換の方法を示すメッセージとともに開くのを断るので、UniVRM か VRM Add-on for Blender で VRM 1.0 に変換してください。

1 GiB を超えるファイルと、glTF の JSON が 64 MiB を超えるファイルは開くのを断ります。`.vrm` の JSON は数 MB です。`src` には、バッファーを `data:` URI で埋め込んだ glTF の JSON ファイル（`.gltf`）も指定できますが、この場合はバッファーも JSON の一部なので、ファイル全体で 64 MiB までです。バッファーや画像を別のファイルに置いたファイルは開くのを断ります。

プラグインはモデルのテクスチャを画像ファイルとしてキャッシュに書き出し、Celesta はそこから読み込みます。キャッシュはユーザーのキャッシュフォルダー（Windows では `%LOCALAPPDATA%`、macOS では `~/Library/Caches`、それ以外では `$XDG_CACHE_HOME` か `~/.cache`）の中の `celesta-plugin-vrm` です。別の場所に置くには、`CELESTA_VRM_TEXTURE_CACHE` に絶対パスを設定します。キャッシュが相対パス、シンボリックリンク、フォルダーでないもの、または（Windows 以外で）ほかのユーザーのものかほかのユーザーが書き込めるものであれば、この変数の名前を示してモデルを開くのを断ります。プラグインはキャッシュを空にすることはありません。

デスクトップアプリの Add メニューでは、**VRM avatar** を選ぶと `.vrm` ファイルを尋ね、16:9 の枠を描きます。

### モーション・コンストレイント・揺れもの

`motions` は VRM アニメーションのクリップ（`.vrma`、`VRMC_vrm_animation` 1.0）を再生し、UniVRM と同じ方法でアバターに当てはめます（リターゲット）。各ボーンはクリップの中と同じだけ基本姿勢から回り、腰（hips）はクリップの移動量を、アバターとクリップの腰の高さの比で拡大・縮小して動きます。モーションは `from` の順に並び、それぞれ次のモーションが始まるまで再生されます。最初のモーションより前は、アバターは基本姿勢で立っています。`loop` を付けたモーションは繰り返し、付けなければ最後の姿勢のまま止まります。クリップに表情の重みがあればそれも使いますが、`expressions` で指定した表情が優先されます。`mouth` か `lipSync` を指定すると母音はすべてそちらで決まり、クリップの口の動きは出ません。どちらも指定しなければ、口はクリップのとおりに動きます。

`tracks` は、モーションのあとに、ボーンを基本姿勢からキーフレームで回します。角度の向きは `lookAt` と同じ（UniVRM と同じ）で、`yaw` はアバターから見て右へ向け、`pitch` は上を向かせ、`roll` は上側をアバターから見て右へ傾けます。負の値は逆向きで、負の `yaw` は左へ向き、負の `pitch` はうつむきます。`hips` の `x`・`y`・`z` はアバター全体をメートル単位で動かします。キーフレームの `frame` は囲んでいるシーケンスのフレームで、小数は最も近いフレームに丸めます。次の例は、歩くクリップを再生し、フレーム 90 から 15 フレームかけて待機のクリップに切り替え、そのあと頭を回して左肩越しに振り返り、また前を向きます。

```tsx
<Vrm
  src="./avatar.vrm"
  motions={[
    { src: './walk.vrma', loop: true },
    { src: './idle.vrma', from: 90, loop: true, fadeIn: 15 },
  ]}
  tracks={{
    head: {
      yaw: [
        { frame: 120, value: 0 },
        { frame: 135, value: -40, easing: 'ease-in-out' },
        { frame: 165, value: -40 },
        { frame: 180, value: 0, easing: 'ease-in-out' },
      ],
    },
  }}
/>
```

アバターのノードコンストレイント（ねじれる袖のように、ほかの部位に付いて動く部品）は、毎フレーム UniVRM と同じ順で追従します。揺れもの（スプリングボーン。髪やスカートなど）は、レイヤーの先頭から 60 Hz の固定の刻みで計算するので、どのフレームも、シークして表示しても、順に再生しても、30 fps でも 60 fps で書き出しても同じになります。`motions` と `tracks` は、レイヤーのフレームを通じて同じ値にしてください。プラグインは揺れものの計算の途中経過をその組み合わせごとに覚えておくので、フレームごとに値が変わると、毎フレーム揺れものをレイヤーの先頭から計算し直すことになります。フレームごとに変わる値は、揺れものが読まない `expressions`・`mouth`・`lookAt` に入れます。

試せるクリップ：[pixiv/three-vrm](https://github.com/pixiv/three-vrm) の `test.vrma`（`packages/three-vrm-animation/examples/models`、MIT）と、BOOTH で無料配布されている VRoid プロジェクトの VRMA モーションパック（ピクシブ）。モーションパックの利用条件では、商用利用はできますが、ファイルの再配布はできません。また、動画を公開する場所に「キャラクターアニメーション: ピクシブ株式会社 VRoidプロジェクト」とクレジットを表記することが求められます。動画を公開する前に、それぞれのクリップの利用条件を確かめてください。

突き当たるかもしれない上限：

- 1 つのレイヤーで開けるクリップは 256 種類までで、ファイルは合わせて 1 GiB まで、読み込んだアニメーションのキーも合わせて 1 GiB までです。
- 揺れものはレイヤーの先頭から 4 時間まで計算します。それより後のフレームは、そう示すエラーになります。揺れものの計算が重いアバター（ノードが 1 万ほどあるもの、揺れものとコライダーの当たり判定が数千あるものなど）はそれより短い時間までしか届きません。モデルを開いたときに警告が出て、届かないフレームは届く時間を示すエラーになります。
- 読まないもの：`VRMC_springBone_limit` の角度制限（モデルにあれば警告が出て、その関節は制限を超えて揺れます）、クリップの `lookAt` のアニメーション、クリップの最初以外の glTF アニメーション。揺れものは `lookAt` や表情には反応しません。
- 足の IK はありません。UniVRM と同じく、基本姿勢がアニメーションより少し高い・低いクリップや、腰の高さのわりに脚が長い・短いアバターでは、足が床に数センチ沈んだり浮いたりすることがあります。

## プラグインを作る

プラグインは最大 2 つの部分からなり、どちらも言語を問いません。

- **コンポーネント**（マニフェストの `module` と `types`）：ES モジュールとその型定義です。Celesta はモジュールをエントリーにバンドルし、その中の `react` と `@celesta/*` の import はアプリ自身のものを使います。音声合成チャンネルはこれだけで作れます。`@celesta/voicevox` と同じく `prepare()` の中で動き、`audio` と `lipSync` を付けたセリフを返します。
- **プログラム**（`executable`、プラットフォームごと）：標準入力でリクエストを読み、標準出力で答えます。レイヤーについては、指定された時刻の 2D のテクスチャ付き三角形メッシュとその色・マスク・合成方法か、3D のシーンを返し、Celesta が描きます。シーンは、スキニングとモーフィングをする三角形のジオメトリーにマテリアルを付けたもので、プログラムが置いたカメラから見て描かれます。Celesta はシーンを奥行きとアンチエイリアス付きで描き、不透明・切り抜き・半透明のマテリアルを扱います。マテリアルは Celesta のライティングなし（unlit）のマテリアルか、プログラムが持ち込むマテリアルです。持ち込むマテリアルは Celesta のマテリアルインターフェースに沿って WGSL で書き、プログラムが送る平行光源と環境光で陰影を付けたり、アウトラインを足したりできます。Celesta はこの WGSL をコンパイルする前に検査します。独自のリソースをバインドすることや、エントリーポイント、ワークグループ変数（`var<workgroup>`。コンピュートシェーダー専用です）、パイプラインで値を上書きする定数（`override`）、WGSL があらかじめ宣言している名前（`clamp` や `vec4f` など）、`celesta` で始まる名前（大文字・小文字を問いません）を宣言することはできません。フレームごとに、モデルのマテリアルアニメーションのようにマテリアルのパラメーターを変えることもできます。そのフレームのレイヤーのキャンバスの大きさを、モデルのものの代わりに指定することもできます（各辺 1〜16384 ピクセル）。これで、コンポーネントは欲しい解像度をレイヤーのデータで渡せます。フレームはモデル・時刻・レイヤーのデータだけで決まるようにしてください。Celesta は、描き直しや書き出しのときなどに、同じフレームをもう一度求めることがあります。モデルを開いたときには、モデルの利用条件のようなお知らせも返せます。お知らせは上で説明したように表示されます。Rust なら `celesta-plugin` クレートを使えます。プロトコル自体は長さ付きの素朴な JSON です。

デスクトップアプリの Add メニューにコンポーネントを出すには、マニフェストの `components` に書きます。

```json
"components": [
  { "name": "Flag", "label": "Flag", "src": "image", "props": { "amplitude": 0.06 } }
]
```

`name` はモジュールが export するコンポーネント名で、英大文字で始まり、英字・数字・`_` が続きます。`label` はメニューに表示する名前です（省略すると `name`）。`src`（`"image"` または `"video"`）があると Image と同じように追加され、アプリはファイルを尋ねて `src`・`x`・`y`・`width` を書きます。`"src": "model"` は、3D モデルのようにプラグインが自分で読むファイルのためのものです。受け取るファイルの種類を `extensions` に（英小文字と数字、ドットなし、重複なし。`["glb"]` など）、レイヤーの幅÷高さを `aspect` に（1/16384〜16384。省略できません）書くと、アプリはその縦横比で枠を描きます。アプリはその種類のファイルだけを受け付け、Image と同じく `src`・`x`・`y`・`width` を書きます。`height` は書かないので、コンポーネント自身の既定の縦横比を `aspect` と同じにしてください。違うと、描いた枠とレイヤーが一致しません。`src` がなければ四角形として描かれ、`x`・`y`・`width`・`height` を書きます。`props` はそのあとに書かれる props です。名前には英字・数字・`_` を使い、値は文字列・数値・真偽値のいずれかで、描いた範囲から書く props と同じ名前は使えません。`components` を持つマニフェストには `module` も必要です。

プラグインの id には英小文字・数字・`-`・`_`・`.` を使い、先頭は英小文字か数字にします。マニフェストで指定するファイルはすべて、プラグインのフォルダー内を指す相対パスにします。`..` を含むパスや、フォルダーの外へ向かうリンクは使えません。これに反するプラグインや、上の決まりに反するコンポーネントを持つプラグインは、理由を示したうえで読み飛ばされます。

両方の部分の作り方はサンプルの README で説明しています。マニフェストとプロトコルはリポジトリの `docs/handoff/2026-11-01-plugin-system.md` で、その後の変更（`components` など）は `docs/handoff/2026-11-02-plugin-*.md` で、3D のシーンとお知らせは `docs/handoff/2026-11-03-plugin-scene-content.md` で、プラグインが持ち込むマテリアル（WGSL）・ライト・描画順・アウトラインは `docs/handoff/2026-11-03-plugin-scene-materials.md` で、VRM プラグインとモデルファイルを受け取るコンポーネントは `docs/handoff/2026-11-03-plugin-vrm.md` で説明しています。
